1. SiteGuard Server Edition ถูกใช้โจมตีเพื่อรันคำสั่งระดับ root หรือ SYSTEM

CVE-2026-106931Active Exploitation18 ต.ค. 2569

JVN และ JPCERT/CC ยืนยันว่ามีการใช้ CVE-2026-106931 โจมตีจริง ช่องโหว่ OS Command Injection อยู่ในฟังก์ชันสถิติของ SiteGuard Server Edition ซึ่งเปิดใช้งานโดยค่าเริ่มต้นและอาจทำให้ผู้โจมตีรันคำสั่งด้วยสิทธิ์สูงสุดของระบบ

สถานการณ์

ช่องโหว่กระทบ SiteGuard Server Edition ตั้งแต่ Ver2.20 เป็นต้นไปเมื่อเปิดฟังก์ชันสถิติ โดยรุ่น IIS ตั้งแต่ Ver3.10 ถึง Ver4.00 Update 4 ไม่ได้รับผลกระทบ JVN ให้คะแนน CVSS v4.0 เท่ากับ 8.5 และยืนยัน Active Exploitation แต่ไม่ได้ระบุผู้โจมตีหรือเหยื่อ

ผลกระทบ

Web Application Firewall ที่ทำงานร่วมกับ Web Server อาจกลายเป็นจุดยึดระบบ หากถูกโจมตีสำเร็จ ผู้โจมตีอาจรันคำสั่งในสิทธิ์ root หรือ SYSTEM กระทบข้อมูล เว็บไซต์ และบริการที่อยู่บนเครื่องเดียวกัน

ข้อเสนอแนะ

อัปเดต Apache/Nginx/IIS เป็น Ver8.00 Update 5 หรือ Apache/Nginx บน FreeBSD เป็น Ver7.00 Update 6 หากอัปเกรดไม่ได้ให้ใช้ Patch ที่ผู้ผลิตจัดให้ รวมทั้งเก็บหลักฐาน ตรวจ Process, File Change และ Log ก่อนแก้ไขระบบ

สถานการณ์

กิจกรรมเกิดระหว่างปลายเมษายนถึงกรกฎาคม 2569 และ GTIG ติดตามผู้ปฏิบัติการในชื่อ UNC7017 โดยยังไม่เชื่อมโยงกับประเทศหรือกลุ่มที่รู้จัก พบผู้ได้รับผลกระทบใน 11 ประเทศและหลายอุตสาหกรรม ผู้โจมตีใช้ CROSSROAD เป็นตัวเริ่มต้นก่อนติดตั้ง SHINYROAD และในบางกรณี Adaptix C2

ผลกระทบ

ซอฟต์แวร์สำรองข้อมูลมักทำงานด้วยสิทธิ์สูง การแก้ไขช่องทางอัปเดตจึงอาจทำให้ Backdoor เข้าถึง Server หรือ Endpoint สำคัญ ขณะที่หน้าต่างโจมตีสั้นทำให้การตรวจสอบแบบ Point-in-time อาจไม่พบหลักฐานบน Server ต้นทาง

ค้นหา AOMEI Backupper และ AnyViewer ในทุกระบบ ตรวจย้อนหลังตั้งแต่เมษายนตาม Detection และ IOC ที่ GTIG เผยแพร่ ตรวจ Scheduled Task และ Child Process ที่ผิดปกติ ปิด SMB/WebDAV ออกสู่อินเทอร์เน็ต และถือว่าระบบที่พบหลักฐานเป็น Incident จนสอบสวนเสร็จ

CVE-2025-61624CISA KEV18 ต.ค. 2569

CISA เพิ่ม CVE-2025-61624 เข้าบัญชี Known Exploited Vulnerabilities เมื่อ 16 ตุลาคม ยืนยันว่าช่องโหว่ Path Traversal ใน CLI ของผลิตภัณฑ์ Fortinet หลายรายการถูกใช้โจมตีจริง

สถานะ: เฝ้าระวังและดำเนินการการดำเนินการ: ตรวจสอบตาม Advisory
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Fortinet ระบุว่าช่องโหว่อนุญาตให้ผู้ดูแลระบบที่ผ่านการยืนยันตัวตนและมีสิทธิ์ Read-write ใช้คำสั่ง CLI บางรายการเขียนหรือลบไฟล์นอกขอบเขตที่กำหนด ผลิตภัณฑ์ที่ระบุรวม FortiOS, FortiPAM, FortiProxy และ FortiSwitchManager โดยรุ่นที่กระทบและรุ่นแก้ไขแตกต่างกันตามผลิตภัณฑ์

ผลกระทบ

บัญชีผู้ดูแลระบบที่ถูกยึดอาจถูกใช้แก้ไขหรือลบไฟล์บนอุปกรณ์เครือข่าย ส่งผลต่อความถูกต้อง การตั้งค่า และความพร้อมใช้ของระบบ ความเสี่ยงสูงขึ้นเมื่ออุปกรณ์เป็นจุดควบคุมการเข้าถึงเครือข่าย

ข้อเสนอแนะ

ตรวจรายการผลิตภัณฑ์และรุ่นกับ Fortinet PSIRT FG-IR-26-122 แล้วอัปเดตตาม Fixed Version ของแต่ละสาย จำกัด Management Interface และ CLI ให้เข้าถึงจากเครือข่ายที่เชื่อถือได้ ตรวจบัญชีผู้ดูแล คำสั่ง CLI และ File Change ที่ผิดปกติ

สถานการณ์

CERT-In ไม่เปิดเผยชื่อองค์กร โมเดล จำนวนเหยื่อ หรือความเสียหายทางการเงิน ช่องทางที่พบรวม Credential ในไฟล์กำหนดค่าและ Repository สาธารณะ API ที่เลิกใช้แต่ยังเปิดอยู่ และ Cloud Role ที่มีสิทธิ์กว้างเกินจำเป็น หลักฐานจึงไม่รองรับการระบุเหยื่อหรือผู้พัฒนา AI รายใด

ผลกระทบ

Automation ช่วยให้การค้นหาและใช้ประโยชน์จากความผิดพลาดพื้นฐานเกิดเร็วและพร้อมกันหลายเป้าหมาย ลดเวลาที่ทีมรักษาความปลอดภัยมีสำหรับตรวจจับและควบคุมเหตุ โดยเฉพาะระบบที่มี Secret รั่วหรือขาด MFA

ข้อเสนอแนะ

แยกสภาพแวดล้อมทดสอบ AI ออกจาก Production ใช้ข้อมูลและ Credential สังเคราะห์ จำกัดปลายทางเครือข่ายและสิทธิ์แบบ Least Privilege สแกน Secret ใน Code/CI/CD เปิด MFA และจัดเก็บ Log แบบตรวจสอบย้อนหลังได้อย่างน้อยตามข้อแนะนำของ CERT-In

5. ConnectWise เพิ่ม IOC และยังระงับ Cloud Backup, SaaS Security และ Cloud Management

Incident UpdateMicrosoft 36518 ต.ค. 2569

ConnectWise อัปเดตเหตุ Cloud Backup เมื่อ 18 ตุลาคม โดยเพิ่ม IP สำหรับตรวจสอบอีกสองรายการ และยืนยันว่าบริการ Cloud Backup, SaaS Security และ Cloud Management ยังถูกระงับระหว่างสอบสวนและกู้คืน

สถานะ: เฝ้าระวังและดำเนินการการดำเนินการ: ตรวจสอบตาม Advisory
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

นี่เป็นความคืบหน้าจากเหตุที่รายงานในฉบับก่อน ผู้ผลิตระบุว่า Backup Archive ยังเข้ารหัส แยกเก็บ และยังไม่พบหลักฐานว่า Archive ถูกเข้าถึง แต่ไม่สามารถยืนยันแทนลูกค้าได้ว่า Microsoft 365 Tenant แต่ละรายไม่มีการเข้าถึงโดยไม่ได้รับอนุญาต จึงยังต้องตรวจ Tenant รายองค์กร

ผลกระทบ

องค์กรที่พึ่งพาบริการดังกล่าวยังไม่สามารถสำรองหรือกู้คืนข้อมูลและใช้ Monitoring/Management บางส่วนได้ ขณะเดียวกัน Credential หรือสิทธิ์ที่ผู้โจมตีเพิ่มผ่าน Identity อื่นอาจไม่ถูกลบเพียงเพราะปิด Application Identity เดิม

ข้อเสนอแนะ

คง Application Identity ที่เกี่ยวข้องไว้ในสถานะปิด เก็บ Sign-in และ Audit Log ตรวจ Credential, Directory Role, Consent Grant, Federation Trust และ Mailbox Rule รวม IOC ที่ผู้ผลิตประกาศล่าสุด และติดตามคำสั่งกู้คืนก่อน Reconnect หรือ Reauthorize
