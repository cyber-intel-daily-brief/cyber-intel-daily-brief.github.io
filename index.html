1. Microsoft Agent Framework บน PyPI ถูกแทรก Credential Stealer

Supply ChainPyPIMicrosoft Agent Framework

แพ็กเกจ agent-framework รุ่น 1.26.1 และ 1.26.2 ถูกปนเปื้อนโค้ดที่ทำงานทุกครั้งเมื่อเริ่ม Python และขโมย Credential จากเครื่องนักพัฒนาและระบบ Build

สถานะ: Malicious Releases Removed; Investigation Ongoingเผยแพร่: 17–18 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

GitHub Advisory Database และ Issue ใน Repository ของ Microsoft Agent Framework ยืนยันว่าแพ็กเกจ agent-framework รุ่น 1.26.1 และ 1.26.2 บน PyPI มีโค้ดอันตรายที่ไม่มีใน Source Repository รุ่นดังกล่าวเพิ่มไฟล์ .pth เพื่อให้ Payload ทำงานทุกครั้งเมื่อ Python เริ่มต้น แม้ Application จะไม่ได้ Import แพ็กเกจโดยตรง ทั้งสองรุ่นถูกนำออกจาก PyPI แล้ว แต่ยังอาจคงอยู่ใน Cache หรือ Internal Mirror

ผลกระทบ

Payload มุ่งเก็บ Environment Variable, Credential File และ Token จาก Cloud Metadata รวมถึง Credential ที่ใช้กับ Azure, Azure DevOps และ GitHub Actions หากติดตั้งบนเครื่องนักพัฒนาหรือ Build Agent ต้องถือว่า Secret ที่เข้าถึงได้จากเครื่องนั้นอาจรั่วไหล แหล่งต้นทางระบุรุ่น 1.26.0 เป็นรุ่นสะอาดล่าสุดก่อนเหตุ แต่ GitHub Advisory ไม่ได้ระบุ Patched Version ใหม่

ข้อเสนอแนะ

ค้นหา agent-framework 1.26.1 และ 1.26.2 ใน Endpoint, CI/CD Log, Lockfile, Wheel Cache และ Internal Mirror กักกันเครื่องที่พบ ลบแพ็กเกจและกลับไปใช้ 1.26.0 ตามคำแนะนำต้นทาง หมุนเวียน Cloud/API/CI Token ที่เครื่องเข้าถึงได้ ตรวจ Audit Log และบังคับใช้ Hash Pinning กับ Dependency

2. Apache Roller RCE ไม่ต้องยืนยันตัวตนถูกใช้โจมตีจริง

Apache RollerCVE-2026-129448Active Exploitation

Apache ยืนยันการโจมตี CVE-2026-129448 ผ่าน XML-RPC Endpoint ซึ่งเปิดทางให้รันคำสั่งจากระยะไกลก่อนยืนยันตัวตน

สถานะ: Active Exploitation Confirmed; Fix Availableเผยแพร่: 17–18 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Apache Software Foundation ออกประกาศ CVE-2026-129448 ระดับ Critical สำหรับ Apache Roller 4.0.0 ถึง 6.1.4 ช่องโหว่เกิดจากการ Deserialization ข้อมูลที่ไม่น่าเชื่อถือใน XML-RPC Endpoint ก่อนตรวจสอบตัวตน ทำให้ผู้โจมตีจากระยะไกลสามารถรันคำสั่งได้ Apache ระบุชัดว่าช่องโหว่นี้กำลังถูกใช้โจมตีจริง แต่ไม่ได้เปิดเผยผู้โจมตีหรือเป้าหมาย

ผลกระทบ

การรันคำสั่งโดยไม่ต้องมีบัญชีอาจนำไปสู่การยึด Web Server, แก้ไขเนื้อหา, ขโมย Credential และใช้ระบบเป็นจุดผ่านเข้าสู่โครงสร้างพื้นฐานอื่น การปิด XML-RPC ผ่านหน้า Administration อย่างเดียวไม่เพียงพอในรุ่นเก่า เพราะระบบ Deserialize คำขอก่อนตรวจค่าดังกล่าว

ข้อเสนอแนะ

อัปเกรดเป็น Apache Roller 6.1.6 หรือใหม่กว่าโดยเร่งด่วน โดยรุ่นปัจจุบันที่หน้าโครงการแนะนำคือ 6.1.7 หากยังอัปเกรดไม่ได้ให้ตั้ง enabledForExtensions=false หรือถอด Servlet Mapping /roller-services/xmlrpc แล้ว Restart ตรวจ Access Log, Process, Web Root และ Outbound Connection เพื่อหาการบุกรุกย้อนหลัง

3. NGINX แก้ช่องโหว่หน่วยความจำใน HTTP/2 ที่อาจนำไปสู่ RCE

NGINXHTTP/2Memory Corruption

CVE-2026-123007 อาจทำให้ Worker ล่ม หน่วยความจำเสียหาย หรือรันคำสั่งได้เมื่อ ASLR ถูกปิดหรือถูกข้าม; รุ่น 1.31.9 และ 1.30.7 แก้ไขแล้ว

สถานะ: Patch Available; No Confirmed Exploitation Reportedเผยแพร่: 18 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

F5 และโครงการ NGINX เปิดเผย CVE-2026-123007 ใน ngx_http_v2_module เมื่อระบบประมวลผล Traffic ที่สร้างเฉพาะ ค่า Flow-control Window อาจเกินขีดจำกัดและทำให้ Heap Buffer Overflow ช่องโหว่กระทบ NGINX ที่เปิด HTTP/2 ตั้งแต่ 1.9.5 ถึง 1.31.8 นอกจากนี้ NGINX ยังแก้ CVE-2026-123634 ซึ่งเป็น Use-after-free ระหว่างการประมวลผล Resolver Response

ผลกระทบ

ผลโดยทั่วไปคือ NGINX Worker Segmentation Fault หรือ Memory Corruption และอาจรันคำสั่งจากระยะไกลได้เมื่อ ASLR ถูกปิดหรือผู้โจมตีสามารถข้าม ASLR ช่องโหว่อยู่ใน Data Plane ไม่ใช่ Control Plane แหล่งต้นทางที่ตรวจสอบไม่ได้รายงานการโจมตีจริงในขณะเผยแพร่

ข้อเสนอแนะ

สำรวจ NGINX Open Source และ NGINX Plus ที่เปิด HTTP/2 โดยเฉพาะระบบ Internet-facing อัปเดตเป็น 1.31.9 หรือ 1.30.7 ขึ้นไปตามสายรุ่น ตรวจ Crash, Core Dump และ Restart ผิดปกติ พร้อมยืนยันว่า ASLR เปิดใช้งานและ Worker ใช้สิทธิขั้นต่ำ

4. OpenJDK Memory Corruption อาจนำไปสู่ RCE ในเงื่อนไขเฉพาะ

OpenJDKCVE-2026-114938Java

CVE-2026-114938 กระทบ JVM บน x86-64 ที่รองรับชุดคำสั่งเฉพาะ เมื่อข้อมูล Base64 จากผู้โจมตีเข้าสู่ Decoder; มีรุ่นแก้ไขแล้ว

สถานะ: Security Update Available; No Confirmed Exploitation Reportedเผยแพร่: 17–18 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

OpenJDK, Oracle และผู้ผลิต Distribution ออกแพตช์ CVE-2026-114938 ซึ่งเป็น Memory Corruption ใน Base64 Intrinsic ของ JVM ช่องโหว่ต้องมีเงื่อนไขร่วม ได้แก่ CPU x86-64 ที่รองรับ AVX-512 และ BMI2, Intrinsic เปิดใช้งาน และมีข้อมูล Base64 ที่ผู้โจมตีควบคุมไหลเข้าสู่ Decoder เช่น Basic Authentication, JWT, SAML, Cookie หรือ TLS Data ระบบ ARM64 ไม่ได้รับผลกระทบตาม CERT-EU

ผลกระทบ

ช่องโหว่อาจทำให้ Denial of Service และในบางเงื่อนไขอาจนำไปสู่การรันคำสั่งโดยไม่ต้องยืนยันตัวตน ผลิตภัณฑ์ที่ฝัง Java Runtime อาจยังได้รับผลกระทบจนกว่าผู้ผลิตของผลิตภัณฑ์จะออกอัปเดต แหล่งต้นทางที่ใช้ในรายงานนี้ไม่ยืนยันการโจมตีจริง

ข้อเสนอแนะ

ตรวจ Runtime และ Hardware ของระบบ Java โดยจัดลำดับ Internet-facing Application ก่อน อัปเดต OpenJDK 17 เป็น 17.0.21.1, 21 เป็น 21.0.13.1 และ 25 เป็น 25.0.5.1 หรือรุ่นแก้ไขจากผู้ผลิต แล้ว Restart JVM หากยังแพตช์ไม่ได้ให้พิจารณาปิด UseBASE64Intrinsics หรือจำกัด AVX ตามคำแนะนำ CERT-EU หลังประเมินผลกระทบด้านประสิทธิภาพ

North East Credit Union และสหกรณ์เครดิตอื่นในไอร์แลนด์แจ้งสมาชิกถึงเหตุ Cybersecurity ที่เกี่ยวข้องกับ Wellington IT ผู้ให้บริการเทคโนโลยีซึ่งใช้โดยสหกรณ์เครดิตเกือบ 50 แห่ง ผู้ให้บริการพบว่าข้อมูลบางส่วนในระบบอาจถูกบุคคลที่ไม่ได้รับอนุญาตเข้าถึง และระบุว่าช่องโหว่ที่เกี่ยวข้องถูกปิดแล้ว

ข้อเสนอแนะ

หน่วยงานการเงินที่ใช้ Wellington IT ให้ตรวจประกาศและรายชื่อข้อมูลที่ได้รับผลกระทบ ประสานผู้กำกับดูแลและแจ้งผู้ใช้ตามกฎหมาย เฝ้าระวังข้อความหรือการโทรที่อ้างข้อมูลผู้รับโอน และย้ำว่าห้ามเปิดเผย PIN, Password หรือ One-time Code พร้อมทบทวนการควบคุม Third-party Access และ Data Minimization
