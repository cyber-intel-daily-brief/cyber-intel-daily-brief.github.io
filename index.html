1. Rackspace Spot ถูกเจาะและเข้าถึง Kubernetes Secrets ของลูกค้า

Rackspace SpotKubernetesCredential Exposure

Rackspace แจ้งลูกค้าว่าผู้โจมตีใช้ข้อมูลรับรองที่รั่วไหลเข้าถึงแพลตฟอร์ม Spot สร้าง Workload ที่ไม่ได้รับอนุญาต และอ่าน Kubernetes Secrets ใน Cluster ที่ได้รับผลกระทบ

สถานะ: Contained; Tokens revoked; Recovery completedเผยแพร่: 21 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

เหตุเกิดเมื่อ 17 พฤศจิกายน ระหว่างประมาณ 00:20–22:00 UTC ผู้โจมตีสามารถดำเนินการเสมือนผู้ใช้ที่ถูกต้อง สร้าง Pod อ่าน Kubernetes Secrets และแสดงรายการ Node กับ Volume ได้ Rackspace ทราบเหตุจากรายงานลูกค้าในวันที่ 18 พฤศจิกายนและคืนบริการเต็มรูปแบบวันที่ 21 พฤศจิกายน

ผลกระทบ

Secret อาจมี Password, API key, Token และข้อมูลรับรองสำหรับ Database, Registry, Cloud storage หรือบริการภายนอก ทำให้ความเสี่ยงขยายออกนอก Cluster แม้ Session เดิมถูกยกเลิกแล้ว

ข้อเสนอแนะ

ออก Spot API token และ Refresh token ใหม่ ดาวน์โหลด kubeconfig ใหม่ หมุนเวียนข้อมูลรับรองทั้งหมดใน Kubernetes Secrets และตรวจ Log ของ Database, Registry, Git repository, Cloud storage และบริการภายนอกย้อนหลังตั้งแต่ 17 พฤศจิกายน

CRITICAL

2. GL.iNet Cloud ถูกใช้ติดตั้ง Malware บน Router และ KVM

GL.iNetRouter/KVMActive Exploitation

GL.iNet ยืนยันว่าบุคคลไม่ได้รับอนุญาตใช้ช่องโหว่ในบริการ Cloud remote management เพื่อติดตั้งซอฟต์แวร์อันตรายบน Router และอุปกรณ์ KVM บางส่วน

สถานะ: Attack path blocked; Firmware updates available/scheduledเผยแพร่: 20–22 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

ผู้ผลิตระบุว่าพบเหตุเมื่อ 20 พฤศจิกายน แก้ช่องโหว่ฝั่ง Cloud และปิดเส้นทางโจมตีแล้ว จึงไม่สามารถติดอุปกรณ์ใหม่ผ่านเส้นทางเดิมได้ แต่การแก้ฝั่ง Cloud ไม่ได้ลบ Malware ออกจากอุปกรณ์ที่ติดเชื้อไปก่อนหน้า และขอบเขตผลกระทบต่อ Computer ที่เชื่อมกับ KVM ยังอยู่ระหว่างสอบสวน

ผลกระทบ

อุปกรณ์ที่ติดเชื้ออาจมี Backdoor หรือ Reverse shell เปิดทางให้ควบคุมเครือข่ายหรือเครื่องที่เชื่อมต่อจากระยะไกล โดยเฉพาะ KVM ที่เข้าถึง Console ของระบบสำคัญ

ข้อเสนอแนะ

ติดตั้ง Stable security firmware ของรุ่นที่ใช้งานทันทีเมื่อมีให้บริการ ใช้ Beta security firmware สำหรับ KVM ที่พบสัญญาณติดเชื้อ ตรวจ Full scan และทำตามคำแนะนำเฉพาะอุปกรณ์จากบัญชี GL.iNet Cloud โดยไม่สรุปว่าปลอดภัยจากการปิดช่องโหว่ Cloud เพียงอย่างเดียว

GL.iNet Security Notice

3. Ghostscript Upload2Shell หลบ -dSAFER และรันคำสั่งจากเอกสาร

GhostscriptCVE-2026-125396Sandbox Escape

CVE-2026-125396 เปิดให้เอกสาร PostScript ที่จัดทำขึ้นเฉพาะหลบ Ghostscript -dSAFER sandbox และรันคำสั่งด้วยสิทธิ์ของ Process ที่ Render เอกสาร

สถานะ: Patch available from upstream/distributions; No in-the-wild exploitation reportedเผยแพร่: 22–23 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Ghostscript มักทำงานอยู่เบื้องหลังระบบ Preview, Thumbnail, Print queue และการแปลงไฟล์ ทำให้ Upload หรือเอกสารที่ดูเหมือน PDF/รูปภาพอาจเข้าถึงช่องโหว่ได้ Debian และ AlmaLinux เผยแพร่คำแนะนำและแพ็กเกจแก้ไขตามสาขาของตนแล้ว

ผลกระทบ

Server ที่รับเอกสารจากผู้ใช้แล้ว Render อัตโนมัติอาจถูกใช้รันคำสั่งในบริบทของบริการ กระทบ Webmail, CMS, ระบบพิมพ์ และ Pipeline แปลงไฟล์ ทั้งนี้ยังไม่มีรายงานยืนยันการใช้โจมตีจริงในธรรมชาติ

ข้อเสนอแนะ

อัปเดต Ghostscript จากผู้จำหน่ายระบบปฏิบัติการหรือแพ็กเกจทางการโดยเร็ว แยก Process Render ด้วย Container/Sandbox เพิ่มเติม จำกัด Network และ Filesystem access และระงับการ Preview เอกสารจากแหล่งไม่น่าเชื่อถือจนกว่าจะอัปเดต

Debian LTS AdvisoryAlmaLinux Advisory

4. OpenRouter ถอดผู้ให้บริการหลังพบความเสี่ยงข้อมูล Prompt ใน AI Supply Chain

AI Supply ChainPrompt LeakageZero Data Retention

OpenRouter ถอดผู้ให้บริการ 3 ราย ลบ 125 Endpoints ออกจากสิทธิ์ Zero Data Retention และแจ้งลูกค้าที่อาจได้รับผลกระทบ หลังงานวิจัย Dragos พบหลักฐาน Prompt รั่วและผู้ให้บริการบางรายถูกเจาะ

สถานะ: Providers off-boarded; Customer notifications issuedเผยแพร่: 22 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Dragos ส่ง Prompt ทดสอบเกือบ 2 ล้านรายการที่ฝัง Canary ระหว่างกรกฎาคม–พฤศจิกายน และพบหลักฐานข้อมูลจากผู้ให้บริการอย่างน้อย 3 รายถูกเปิดเผย รวมถึงกรณี Privacy setting ไม่ถูกปฏิบัติตาม OpenRouter ระบุว่าไม่พบการเจาะระบบของ OpenRouter เอง แต่กำลังตรวจสอบเส้นทางประมวลผลและเรียกร้องหลักฐานก่อนคืนสิทธิ์ ZDR

ผลกระทบ

Prompt อาจมี Source code, Credential, ข้อมูลลูกค้า หรือเอกสารภายใน การมี Router และ Reseller หลายชั้นทำให้ข้อมูลเดินทางผ่านผู้ประมวลผลที่ลูกค้าอาจไม่ทราบและเพิ่มความเสี่ยง Supply-chain

ข้อเสนอแนะ

ตรวจรายการ Model/Provider ที่ใช้งาน หมุนเวียน Secret ที่เคยใส่ใน Prompt เปิด ZDR เมื่อรองรับ ห้ามส่ง Production credential เข้า Agent context และกำหนด Contract/Technical control ให้ระบุเส้นทางผู้ประมวลผลและ Data residency อย่างชัดเจน

5. Cleverbridge ยืนยันข้อมูลบัตรชำระเงินถูกคัดลอกจากแพลตฟอร์ม

CleverbridgePayment Card DataData Breach

Cleverbridge ระบุว่าบุคคลที่สามคัดลอกข้อมูลบัตรชำระเงินจากแพลตฟอร์ม; หนังสือแจ้งผู้ได้รับผลกระทบระบุ Card number, Expiry date และ CVV/CVC

สถานะ: Contained; Notifications and investigation ongoingเผยแพร่: 20–22 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

บริษัทตรวจพบกิจกรรมไม่ได้รับอนุญาตเมื่อ 4 พฤศจิกายนและนำระบบลงชั่วคราวเพื่อควบคุมเหตุ ก่อนเริ่มแจ้งผู้ได้รับผลกระทบวันที่ 20 พฤศจิกายน บริษัทระบุว่าเหตุไม่ใช่ Ransomware และไม่มีระบบถูกเข้ารหัส แต่ยังไม่เปิดเผยจำนวนผู้ได้รับผลกระทบหรือวิธีที่ผู้โจมตีเข้าถึงระบบ

ผลกระทบ

ข้อมูลหมายเลขบัตร วันหมดอายุ และรหัส CVV/CVC สามารถเพิ่มความเสี่ยงธุรกรรม Card-not-present และ Fraud โดยตรง แม้ประกาศบางฉบับระบุว่าไม่มีข้อมูลส่วนบุคคลประเภทอื่นถูกคัดลอก

ข้อเสนอแนะ

ผู้ได้รับแจ้งควรตรวจรายการเดินบัญชี ติดต่อผู้ออกบัตรเพื่อพิจารณาเปลี่ยนบัตรและตั้ง Fraud alert องค์กรที่ใช้ Cleverbridge ควรเตรียมข้อความสื่อสารลูกค้าและตรวจสอบการปฏิบัติตาม PCI DSS กับผู้ประมวลผล
