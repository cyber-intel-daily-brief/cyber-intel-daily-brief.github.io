01 สถานการณ์

Fortinet เผยแพร่และปรับปรุงคำแนะนำ FG-IR-26-175 สำหรับ CVE-2026-104286 ซึ่งเป็นช่องโหว่ Path Traversal และการจัดการ NULL Byte ที่ไม่เหมาะสมใน FortiMail ผู้โจมตีที่ไม่ผ่านการยืนยันตัวตนสามารถส่งคำขอ HTTP/HTTPS ที่สร้างขึ้นเฉพาะเพื่อเขียนไฟล์ลงระบบได้ Fortinet ยืนยันว่ามีการนำช่องโหว่นี้ไปใช้โจมตีจริง และ CISA เพิ่มเข้าสู่ Known Exploited Vulnerabilities Catalog แล้ว

02 ผลกระทบ

หากโจมตีสำเร็จ ผู้โจมตีอาจแก้ไขไฟล์หรือนำโค้ดอันตรายเข้าสู่อุปกรณ์ที่ทำหน้าที่เป็นด่านหน้าในการรับส่งอีเมล ส่งผลต่อความลับของข้อมูล ความถูกต้องของระบบ และความต่อเนื่องของบริการ อุปกรณ์ที่เปิด Webmail หรือส่วนที่เกี่ยวข้องกับ IBE ให้เข้าถึงจากอินเทอร์เน็ตมีความเสี่ยงสูงเป็นพิเศษ

03 ข้อเสนอแนะ

ให้ตรวจสอบ FortiMail ทุกเครื่องและรุ่นที่ใช้งาน อัปเดตเป็นรุ่นแก้ไขตาม FG-IR-26-175 โดยเร่งด่วน และจำกัด Webmail/Management Access ให้เข้าถึงจากเครือข่ายที่เชื่อถือได้ ระหว่างดำเนินการให้ตรวจสอบ IOC และ Log ตามที่ Fortinet ระบุ พร้อมเก็บหลักฐานก่อนแก้ไข หากพบความผิดปกติให้แยกระบบและดำเนินการตามกระบวนการตอบสนองเหตุการณ์

01 สถานการณ์

Atlassian เผยแพร่คำแนะนำเมื่อ 5 ตุลาคม 2569 สำหรับ CVE-2026-21589 ซึ่งกระทบผลิตภัณฑ์ Data Center หลายรายการในทุกเวอร์ชันก่อนรุ่นแก้ไข ช่องโหว่อนุญาตให้ผู้โจมตีที่ไม่ผ่านการยืนยันตัวตนเข้าถึงไฟล์เฉพาะภายใน Web Application Root โดยต้องทราบชื่อและพาธของไฟล์เป้าหมายล่วงหน้า Atlassian ระบุว่ายังไม่พบหลักฐานการนำช่องโหว่นี้ไปใช้โจมตี และผลิตภัณฑ์ Cloud ได้รับการแก้ไขแล้ว

02 ผลกระทบ

ไฟล์ที่ถูกเปิดเผยอาจมีข้อมูลกำหนดค่า ความลับของระบบ หรือข้อมูลที่ช่วยให้ผู้โจมตีดำเนินการขั้นต่อไป ทั้งนี้ผลกระทบจริงขึ้นอยู่กับไฟล์ที่มีอยู่ในแต่ละการติดตั้ง ระบบที่เปิดให้เข้าถึงจากอินเทอร์เน็ตควรได้รับการจัดลำดับแก้ไขก่อน

03 ข้อเสนอแนะ

ให้สำรวจผลิตภัณฑ์ Atlassian Data Center ที่ใช้งานและเปรียบเทียบกับรุ่นแก้ไขใน Advisory โดยตรง จากนั้นติดตั้ง Patch หรืออัปเกรดเป็นรุ่นที่ผู้ผลิตกำหนด หากยังแก้ไขไม่ได้ให้ถอดระบบออกจากอินเทอร์เน็ตหรือใช้มาตรการชั่วคราวของ Atlassian พร้อมตรวจสอบ Access Log สำหรับคำขอพาธผิดปกติย้อนหลัง

03 ข้อเสนอแนะ

ข้อมูลชื่อและช่องทางติดต่อสามารถนำไปใช้ทำ Phishing หรือ Social Engineering ที่มีความน่าเชื่อถือมากขึ้น การยึดช่องทาง Push Notification ขององค์กรยังอาจทำให้ผู้โจมตีส่งลิงก์หรือข้อความหลอกลวงถึงผู้ใช้จำนวนมากโดยอาศัยความน่าเชื่อถือของแอป

03 ข้อเสนอแนะ

ให้องค์กรตรวจสอบสิทธิ์ API Key, Service Account และบัญชีผู้ดูแลของแพลตฟอร์มสื่อสารลูกค้า เพิกถอน Token ที่ไม่จำเป็นและบังคับใช้ MFA กับบัญชีสิทธิ์สูง ตรวจสอบประวัติการส่งข้อความและการเปลี่ยนค่า Configuration หากพบการส่งข้อความผิดปกติให้แจ้งผู้ใช้ผ่านช่องทางที่ยืนยันได้และเฝ้าระวัง Phishing ที่ตามมา

01 สถานการณ์

BleepingComputer รายงานผลการวิจัยของ Island เกี่ยวกับแคมเปญ Phishing ที่สร้างเว็บไซต์เลียนแบบบริการ AI และมุ่งเป้าบุคลากรด้านโฆษณา Media Buyer และผู้ดูแลบัญชี เมื่อผู้ใช้กดเชื่อมต่อ ระบบจะแสดงหน้าต่าง Google Login ปลอมแบบ Browser-in-the-Browser ซึ่งทำให้แถบที่อยู่ดูเหมือน accounts.google.com ผู้ควบคุมการโจมตีสามารถโต้ตอบแบบ Real Time และร้องขอ Password, Authenticator Code, SMS Code หรือ Push Approval ได้

02 ผลกระทบ

หากผู้ใช้กรอกข้อมูล ผู้โจมตีอาจยึดบัญชีโฆษณาที่เชื่อมต่อกับลูกค้าหลายราย ใช้งบประมาณเพื่อเผยแพร่โฆษณาทุจริต หรือเข้าถึงข้อมูลธุรกิจเพิ่มเติม แม้เปิดใช้ MFA แล้วก็ยังเสี่ยงหากผู้ใช้ส่งรหัสหรืออนุมัติคำขอจากหน้าหลอกลวง

03 ข้อเสนอแนะ

ให้บล็อกโดเมนเลียนแบบที่ตรวจพบจากแหล่งที่เชื่อถือได้ และกำชับผู้ใช้ให้ตรวจสอบ URL ของหน้าหลักแทนการเชื่อถือหน้าต่าง Login ที่ซ้อนอยู่ในเว็บ ใช้ Passkey หรือ Hardware Security Key เมื่อรองรับ จำกัดสิทธิ์บัญชีโฆษณาตามหน้าที่ และเฝ้าระวัง Login, Token และ Campaign ที่ผิดปกติ หากสงสัยว่าถูกหลอกให้เปลี่ยนรหัสผ่านและเพิกถอน Session/Token ทันที

7. Nikkei เปิดเผยบัญชี Google Workspace และ Microsoft 365 ถูกเข้าถึงและใช้ส่ง Phishing

Nikkei reports compromise of employee cloud email accounts

HIGH
Google WorkspaceMicrosoft 365PhishingAccount Compromise

Nikkei เปิดเผยเหตุบัญชีอีเมลพนักงานสองบัญชีถูกเข้าถึงในคนละช่วงเวลา โดยบัญชี Microsoft 365 หนึ่งบัญชีถูกใช้ส่งอีเมล Phishing ประมาณ 9,000 ฉบับ ขณะที่เหตุ Google Workspace อาจเปิดเผยชื่อและอีเมลของบุคลากรและคู่ค้าจำนวน 1,646 ราย

01 สถานการณ์

Nikkei เปิดเผยว่าบัญชี Google Workspace ของพนักงานถูกเข้าถึงในเดือนกรกฎาคม และบริษัทเปลี่ยนรหัสผ่านหลังได้รับแจ้งจาก Google ในเดือนสิงหาคม เหตุการณ์ดังกล่าวอาจเปิดเผยชื่อและอีเมลของพนักงานและคู่ค้า 1,646 ราย ต่อมาในเดือนกันยายน บัญชี Microsoft 365 ของพนักงานอีกคนถูกเข้าถึงและใช้ส่งอีเมล Phishing ประมาณ 9,000 ฉบับไปยังบุคลากรและผู้ที่เคยติดต่อกับพนักงาน

02 ผลกระทบ

บัญชีอีเมลที่ถูกยึดสามารถใช้ส่งข้อความจากโดเมนจริงขององค์กร ทำให้ Phishing มีความน่าเชื่อถือและอาจนำไปสู่การขโมยข้อมูลรับรองหรือยึดบัญชีเพิ่ม รายชื่อผู้ติดต่อที่เปิดเผยยังอาจถูกนำไปใช้สร้างข้อความหลอกลวงแบบเจาะจงในภายหลัง

03 ข้อเสนอแนะ

ให้ตรวจสอบ Sign-in Log, Mailbox Rule, OAuth Consent และ Session ของบัญชี Cloud Email โดยเฉพาะบัญชีที่มีการส่งอีเมลจำนวนมากผิดปกติ บังคับใช้ MFA แบบต้าน Phishing จำกัด Legacy Authentication และตั้ง Alert สำหรับ Impossible Travel หรือ Mass Mailing หากยืนยันการยึดบัญชีให้เปลี่ยนรหัสผ่าน เพิกถอน Session และแจ้งผู้รับให้ลบข้อความอันตราย
