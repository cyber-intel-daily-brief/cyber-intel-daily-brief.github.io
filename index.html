1. Barracuda เชื่อมโยงเหตุ Cloud Intrusion กับ ARTEX หลัง Access Key ของคู่ค้ารั่ว

BarracudaARTEXCloud Credentials

ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Barracuda เปิดเผยผลสอบสวนเพิ่มเติมว่า Cloud Access Key ที่บริษัทเคยออกให้ผู้ให้บริการ AI ถูกเก็บใน Configuration File ภายใน GitHub Repository ของคู่ค้า และรั่วเมื่อ Development Environment ของคู่ค้าถูกเจาะ ผู้โจมตีเริ่มใช้กุญแจเมื่อ 1 พฤศจิกายน ก่อนค้น Secret และ Credential เพื่อขยายการเข้าถึงผ่าน Cloud Account, Data Analytics, Source Code และ Kubernetes รวมประมาณ 10 Cloud Account ภายใน 44 ชั่วโมง ลักษณะชื่อ Resource และขั้นตอนอัตโนมัติสอดคล้องกับกรอบงาน ARTEX แต่ข้อมูลนี้ระบุวิธีดำเนินการ ไม่ใช่การยืนยันตัวผู้โจมตี

ผลกระทบ

ผู้โจมตีอ่าน Secret Store, Infrastructure-as-code State, Server Metadata และ Kubernetes Service Account แล้วใช้ Credential ที่พบเป็นเส้นทางต่อไป รวมถึงวาง Container สำหรับอ่าน File System และพยายามสร้าง Cloud Identity ระดับผู้ดูแล ระบบป้องกันบล็อกความพยายามสร้าง Identity และ Barracuda ระบุว่าได้ควบคุมเหตุ หมุนเวียน Credential และติดต่อเฉพาะลูกค้าที่อาจได้รับผลกระทบแล้ว

ข้อเสนอแนะ

ลูกค้าที่ได้รับแจ้งจาก Barracuda ให้เพิกถอนและสร้าง Integration Credential ใหม่ทันที พร้อมตรวจ Activity ในระบบที่เชื่อมต่อย้อนหลังตั้งแต่ 1 พฤศจิกายน 2569 องค์กรทั่วไปควรสำรวจ Long-lived Cloud Key ที่มอบแก่คู่ค้า เปลี่ยนเป็น Short-lived Federated Identity จำกัดสิทธิ Service Account และตรวจ CI/CD Log ว่ามี Workflow หรือ Branch ผิดปกติที่พยายามพิมพ์ Secret หรือไม่

2. Copeland XWEB EVO ถูกสแกนโจมตีหลังเปิดเผยช่องโหว่ไม่นาน

OT / RefrigerationCopeland XWEB EVOActive Probing

VulnCheck พบการพยายามใช้ CVE-2026-124014 ภายในไม่ถึง 2 ชั่วโมง และตรวจพบการสแกน CVE-2026-124010 สำหรับสั่งคำสั่งระดับ Root

สถานะ: Exploitation Attempts Observed; Legacy Product EOLเผยแพร่: 13–16 พ.ย. 2569

สถานการณ์

VulnCheck เปิดเผยช่องโหว่ 14 รายการใน Copeland/Dixell XWEB EVO ซึ่งใช้ควบคุมและติดตามระบบทำความเย็น โดยยืนยันในห้องทดลองว่าทุกรายการสามารถนำไปสู่สิทธิ uid=0(root) ได้ เซนเซอร์ Canary ตรวจพบความพยายามใช้ CVE-2026-124014 ซึ่งเขียน Configuration ได้โดยไม่ต้องยืนยันตัวตนภายในประมาณ 1 ชั่วโมง 40 นาทีหลังข้อมูล CVE เผยแพร่ และต่อมาพบการสแกน CVE-2026-124010 ซึ่งรันคำสั่งระดับ Root โดยไม่ต้องยืนยันตัวตน

ผลกระทบ

ช่องโหว่ที่ถูกสแกนกระทบ Firmware รุ่นเก่าก่อนการเขียนระบบใหม่ปี 2021 และอุปกรณ์รุ่นนี้สิ้นสุดการสนับสนุนซอฟต์แวร์เมื่อ 16 มีนาคม 2569 การยึด Controller อาจเปิดทางให้เปลี่ยนค่าควบคุม ทำให้ระบบหยุดชะงัก หรือใช้เป็นจุดผ่านเข้าสู่เครือข่าย OT ทั้งนี้ VulnCheck ระบุว่าการสแกนครั้งนี้เป็นการโจมตีแบบฉวยโอกาสและไม่ใช่หลักฐานเชื่อมโยงกับเหตุทำลายระบบทำความเย็นในฝรั่งเศส

ข้อเสนอแนะ

ค้นหา XWEB EVO ในทรัพย์สิน OT และนำออกจากการเชื่อมต่ออินเทอร์เน็ตทันที จำกัดการเข้าถึงผ่าน VPN และ Allowlist แยก VLAN/Firewall จากเครือข่ายธุรกิจ ตรวจ Web/CGI Log และ Configuration Change หลัง 12 พฤศจิกายน และวางแผนย้ายไปผลิตภัณฑ์ที่ยังได้รับการสนับสนุน เช่น XWEB Pro ตามคำแนะนำผู้ผลิต

3. NoisyTCP กระทบ Linux Kernel และอาจทำให้ Server ล่มจากระยะไกลก่อนยืนยันตัวตน

Linux KernelCVE-2026-99288Remote DoS

CVE-2026-99288 เป็น Race Condition ใน TCP Request Socket; ผู้วิจัยทำให้ Nginx, Apache และ SSH บน VM ล่มได้ภายในประมาณ 5 วินาทีถึง 2 นาที

สถานะ: Patch Available; No Confirmed Exploitationเผยแพร่: 15–16 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

นักวิจัยเปิดเผย NoisyTCP หรือ CVE-2026-99288 ซึ่งเป็น Race Condition ใน Linux Kernel TCP Stack ที่เกิดระหว่างการค้นหา Connection เดิมและการจัดการ Reference ของ Request Socket ช่องโหว่อยู่ใน Kernel มาตั้งแต่ 3 ตุลาคม 2558 และได้รับการแก้ใน Upstream Commit 4e2b3ef19e0e เมื่อ 3 พฤศจิกายน 2569 ระบบที่มี RX Queue ตั้งแต่สองชุดหรือกระจาย Packet Processing หลาย CPU มีเส้นทางถูกกระตุ้นได้

ผลกระทบ

ผู้โจมตีจากภายนอกที่ไม่ต้องยืนยันตัวตนสามารถส่ง Packet ที่สร้างเฉพาะเพื่อทำให้ Kernel Memory เสียหายและ Server หยุดทำงาน ผู้วิจัยรายงานว่า Nginx, Apache และ SSH ค่าเริ่มต้นบน QEMU/KVM อาจถูกทำให้ล่มได้ภายในประมาณ 5 วินาทีถึง 2 นาที ส่วน Bare-metal ที่เงียบต้องใช้เวลานานกว่ามาก ยังไม่พบข้อมูลยืนยันการโจมตีจริงจากแหล่งอ้างอิง

ข้อเสนอแนะ

ตรวจประกาศ Kernel Package ของ Linux Distribution ที่ใช้งาน ติดตั้งรุ่นที่รวม Fix และ Reboot เพื่อใช้งาน Kernel ใหม่โดยเร็ว ระบบสำคัญที่ยังอัปเดตไม่ได้อาจลด RX Queue/RPS เป็นทางชั่วคราว หรือปิด SYN Cookie ตามคำแนะนำผู้วิจัยหลังประเมินความเสี่ยง SYN Flood โดยต้องใช้ค่ากับทุก Network Namespace/Container ที่แยกออกมา

ผลกระทบ

ข้อเสนอแนะ

ผู้ที่ซื้อบัตรผ่าน Fandango ในช่วงดังกล่าวควรตรวจ Statement และตั้งแจ้งเตือนธุรกรรม ติดต่อผู้ออกบัตรเพื่อเปลี่ยนบัตรหากพบรายการผิดปกติ และระวังอีเมลที่อ้างการคืนเงินหรือยืนยันการซื้อ สำหรับผู้ดูแลเว็บไซต์ให้ตรวจ Integrity ของ Checkout Script, Content Security Policy และการเปลี่ยนแปลง Third-party Tag อย่างต่อเนื่อง

สถานการณ์

Coles Group แจ้งตลาดหลักทรัพย์ออสเตรเลียเมื่อ 16 พฤศจิกายนว่ากำลังสอบสวนเหตุ Cybersecurity และทำงานร่วมกับ Australian Cyber Security Centre หน่วยงานกำกับ และผู้เชี่ยวชาญภายนอกเพื่อควบคุมและทำให้สภาพแวดล้อม IT ปลอดภัย บริษัทยังไม่เปิดเผยช่องทางการโจมตีหรือขอบเขตเชิงเทคนิค

ผลกระทบ
