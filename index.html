01 สถานการณ์

Atlassian เผยแพร่คำแนะนำเมื่อ 5 ต.ค. 2569 สำหรับ CVE-2026-21589 ซึ่งเป็นช่องโหว่ Arbitrary File Access ที่กระทบ Bitbucket Data Center, Confluence Data Center, Jira Service Management Data Center, Jira Software Data Center, Bamboo Data Center, Crowd Data Center, Crucible และ Fisheye ผู้โจมตีที่ไม่ผ่านการยืนยันตัวตนอาจเข้าถึงไฟล์เฉพาะใน Web Application Root ได้หากทราบชื่อและพาธล่วงหน้า ต่อมา BleepingComputer รายงานว่า Previdian ตรวจพบความพยายามใช้ช่องโหว่นี้บน Honeypot เมื่อ 7 ต.ค. ภายหลังมีการเผยแพร่รายละเอียดเทคนิค จึงควรถือเป็นสัญญาณเร่งด่วน แม้สถานะดังกล่าวเป็นรายงานจากผู้วิจัยและยังไม่ใช่การยืนยันจาก Atlassian หรือ CISA KEV ณ เวลาตัดข้อมูล

02 ผลกระทบ

หากโจมตีสำเร็จ ผู้โจมตีอาจอ่านไฟล์ที่มีข้อมูลกำหนดค่า ความลับของระบบ หรือข้อมูลที่ช่วยให้ดำเนินการโจมตีขั้นต่อไปได้ ผลกระทบขึ้นอยู่กับไฟล์ที่มีอยู่ในแต่ละระบบ โดยเฉพาะ Instance ที่เปิดให้เข้าถึงจากอินเทอร์เน็ตมีความเสี่ยงสูงกว่า

03 ข้อเสนอแนะ

ให้ตรวจสอบผลิตภัณฑ์และเวอร์ชัน Atlassian Data Center ที่ใช้งานและอัปเดตเป็นรุ่นแก้ไขตาม Advisory โดยเร็ว หากยัง Patch ไม่ได้ ให้ถอดระบบออกจากอินเทอร์เน็ตหรือใช้ WAF/Reverse Proxy Mitigation ตามที่ผู้ผลิตระบุ พร้อมตรวจ Access Log ย้อนหลังเพื่อค้นหาคำขอผิดปกติ หากพบหลักฐานการเข้าถึงไฟล์โดยไม่ได้รับอนุญาตให้เก็บหลักฐานและดำเนิน Incident Response ทันที

2. FBI และ U.S. Secret Service เตือน FortiBleed ยังโจมตี FortiGate และ SSL VPN ต่อเนื่อง

CRITICAL
FortiBleedFortiGateSSL VPNCredential CompromiseRansomware

FBI และ U.S. Secret Service เตือนว่าแคมเปญ FortiBleed ยังสแกนและเข้าถึง Fortinet FortiGate/SSL VPN ที่เปิดสู่อินเทอร์เน็ต โดยใช้รหัสผ่านที่รั่วไหลหรือใช้ซ้ำและข้อมูลรับรองที่ถูกขโมย ผู้โจมตีบางกรณีสร้างบัญชีใหม่ เปลี่ยนหรือลบบัญชีเดิมจนผู้ดูแลถูกล็อกออก และมีการเชื่อมโยงการเข้าถึงลักษณะนี้กับ Initial Access สำหรับ Ransomware

01 สถานการณ์

รายงานวันที่ 6–7 ต.ค. 2569 อ้างคำเตือนร่วมของ FBI และ U.S. Secret Service ว่า FortiBleed เป็นแคมเปญ Credential Compromise ที่ยังดำเนินอยู่ต่อ Fortinet FortiGate และ SSL VPN Gateway ที่เปิดสู่อินเทอร์เน็ต การโจมตีอาศัยรหัสผ่านที่รั่วไหลหรือใช้ซ้ำ การทำ Password Spraying/Credential Stuffing และการนำข้อมูลยืนยันตัวตนไปถอดรหัสแบบ Offline รายงานของ SOCRadar ระบุว่าตรวจยืนยันอุปกรณ์ที่ถูกกระทบมากกว่า 86,644 เครื่องใน 194 ประเทศ และพบกรณีผู้โจมตีสร้างบัญชีผู้ดูแลใหม่ รวมถึงเปลี่ยนหรือลบบัญชีเดิมเพื่อรักษาการเข้าถึง

02 ผลกระทบ

หากอุปกรณ์ขอบเครือข่ายถูกยึด ผู้โจมตีอาจควบคุมช่องทาง Remote Access, ล็อกผู้ดูแลออกจากอุปกรณ์, สำรวจบัญชีภายในและพยายามเคลื่อนย้ายเข้าสู่เครือข่ายองค์กร การเข้าถึงจาก FortiBleed ยังถูกกล่าวถึงว่าเป็นจุดเริ่มต้นที่ถูกนำไปใช้โดย Ransomware Affiliate บางกลุ่ม จึงมีความเสี่ยงต่อการหยุดชะงักของระบบและการเข้ารหัสข้อมูลในขั้นต่อไป

03 ข้อเสนอแนะ

ให้ยกเลิกหรือจำกัดการบริหาร FortiGate จากอินเทอร์เน็ตให้เหลือเฉพาะ Trusted Hosts ยุติ Admin/VPN Sessions ที่ใช้งานอยู่และเปลี่ยนรหัสผ่านที่เกี่ยวข้อง บังคับใช้ Phishing-resistant MFA สำหรับ Remote Access ตรวจบัญชีผู้ดูแล REST API Key และ Configuration เทียบกับ Baseline พร้อมตรวจ Firewall/VPN/Authentication Log ย้อนหลัง หากพบความผิดปกติให้เตรียม Out-of-Band Administrative Recovery และแยกอุปกรณ์เพื่อทำ Incident Response

01 สถานการณ์

Lumen Black Lotus Labs เปิดเผย PoeLLM ซึ่งเป็น Malware ที่ใช้และโจมตี AI/LLM Infrastructure และ Open-source Service ที่เปิดสู่อินเทอร์เน็ต โดยพบ LiteLLM, Ollama, Gotenberg และ Gitea เป็นเป้าหมายหลัก รวมถึงมีข้อบ่งชี้การมุ่งเป้า Ivanti Sentry ด้วย Malware ใช้กลไก C2 ที่คำนวณที่อยู่ Server จากคำสำคัญในบทกวีที่โฮสต์บน GitHub และมีการใช้งานเพื่อขุด Cryptocurrency ด้วย XMRig/Iron รวมทั้งใช้เครื่องที่ถูกยึดเป็น Scanner และ Exploit Server เพื่อหาเหยื่อรายใหม่ Black Lotus Labs ระบุว่ากิจกรรมเพิ่มขึ้นอย่างมากและกระทบมากกว่า 3,400 Server

02 ผลกระทบ

ระบบ AI/LLM ที่ถูกยึดอาจสูญเสียทรัพยากรประมวลผลจาก Cryptomining ทำให้บริการช้าหรือไม่เสถียร และอาจถูกนำไปใช้เป็นฐานยิงการสแกนหรือโจมตีระบบอื่น นอกจากนี้ AI Server มักเข้าถึงข้อมูลภายใน โมเดล หรือ Secret ของระบบพัฒนา จึงควรประเมินความเสี่ยงต่อข้อมูลและ Credential ควบคู่กัน

03 ข้อเสนอแนะ

ให้สำรวจ AI/LLM Service และเครื่องมือ Open-source ที่เปิดจากอินเทอร์เน็ต โดยเฉพาะ LiteLLM, Ollama, Gotenberg และ Gitea ตรวจสอบให้เป็นรุ่นล่าสุดและจำกัด Port/Service ให้เข้าถึงเฉพาะแหล่งที่จำเป็น ตรวจ Network Log เทียบกับ IOC ที่ Black Lotus Labs เผยแพร่ และตรวจ CPU/GPU Usage, Process และการสแกนออกจาก Server ที่ผิดปกติ หากพบการติดเชื้อให้แยกเครื่อง เปลี่ยน Credential/Token ที่เกี่ยวข้อง และตรวจระบบข้างเคียง

01 สถานการณ์

SonicWall เผยแพร่ Security Advisory SNWLID-2026-0017 เมื่อ 6 ต.ค. 2569 ครอบคลุมหลายช่องโหว่ใน SMA1000 โดย CVE-2026-102255 เป็น Pre-authentication Server-Side Request Forgery (SSRF) ใน Appliance Work Place ที่เกิดจาก Alternate Access Path ที่ไม่ตั้งใจ ผู้โจมตีจากระยะไกลไม่ต้องมีสิทธิ์สามารถทำให้อุปกรณ์ส่งคำขอแทนตนเพื่อเข้าถึงฟังก์ชันภายในและดำเนินการที่ไม่ได้รับอนุญาต CERT-FR ระบุรุ่นที่แก้ไขเป็น 12.5.0-03082 และ 12.4.3-03670 ขณะที่ SonicWall ระบุว่ายังไม่มีหลักฐานการโจมตีจริง ณ เวลาประกาศ

02 ผลกระทบ

SMA1000 เป็นระบบ Secure Remote Access ที่อยู่บริเวณขอบเครือข่าย หากช่องโหว่ถูกใช้สำเร็จ ผู้โจมตีอาจใช้ Appliance เป็นตัวกลางเข้าถึงฟังก์ชันภายในที่ไม่ควรเปิดโดยตรง ส่งผลต่อความลับและความถูกต้องของระบบ และเพิ่มโอกาสในการใช้ Remote Access Gateway เป็นจุดเริ่มต้นสำหรับการโจมตีต่อเนื่อง

03 ข้อเสนอแนะ

ให้ตรวจสอบ SMA1000 6210, 7210 และ 8200v ที่ใช้งานและติดตั้ง Hotfix/รุ่นแก้ไขตาม SNWLID-2026-0017 โดยเร็ว จำกัดการเข้าถึง Work Place และ Management Interface จากอินเทอร์เน็ตเท่าที่จำเป็น และตรวจ Log สำหรับ Request ที่ผิดปกติหรือการเข้าถึงฟังก์ชันภายในที่ไม่สอดคล้องกับการใช้งานปกติ หากยังอัปเดตไม่ได้ให้ลด External Exposure ชั่วคราวจนกว่าจะดำเนินการเสร็จ

Google อัปเดต Stable Channel เมื่อ 6 ต.ค. 2569 เป็น Chrome 155.0.8059.39/.40 สำหรับ Windows และ macOS และ 155.0.8059.39 สำหรับ Linux โดยระบุว่ารุ่นนี้มี Security Fixes 247 รายการ ในจำนวนนี้มีช่องโหว่ Critical 4 รายการ ได้แก่ CVE-2026-106382, CVE-2026-106197, CVE-2026-106358 และ CVE-2026-106347 ซึ่งเป็น Use-after-Free ในองค์ประกอบต่าง ๆ ของ Browser ไม่พบข้อความจาก Google ในประกาศรอบนี้ว่าช่องโหว่ดังกล่าวถูกใช้โจมตีจริง

02 ผลกระทบ

ช่องโหว่หน่วยความจำระดับ Critical ใน Browser อาจนำไปสู่การทำงานผิดพลาดหรือการรันโค้ดในบริบทของ Browser ขึ้นอยู่กับเงื่อนไขของแต่ละช่องโหว่ เครื่องผู้ใช้ที่ยังไม่อัปเดตและมีการเปิดเว็บไซต์หรือเนื้อหาที่ไม่น่าเชื่อถือจึงมีความเสี่ยงสูงกว่าระบบที่ได้รับการแก้ไขแล้ว

03 ข้อเสนอแนะ

ให้ตรวจสอบ Chrome เวอร์ชันบน Windows, macOS และ Linux ในองค์กร อัปเดตเป็น Chrome 155 รุ่น Stable ที่ Google กำหนดและ Relaunch Browser เพื่อให้ Patch มีผล สำหรับเครื่องที่บริหารผ่าน Enterprise Policy ให้ตรวจ Compliance ของ Version และติดตามเครื่องที่อัปเดตไม่สำเร็จ พร้อมเฝ้าระวัง Browser Crash หรือพฤติกรรมผิดปกติหลังเข้าชมเว็บไซต์ที่ไม่ทราบแหล่งที่มา

6. Southern Company แจ้งเหตุข้อมูลลูกค้ากลุ่มธุรกิจไฟฟ้าราว 400,000 บัญชีถูกเข้าถึง

Southern Company reports unauthorized access to roughly 400,000 utility customer accounts

HIGH
Critical InfrastructureElectric UtilityData BreachCustomer Portal

Southern Company แจ้งเหตุบุคคลที่ไม่ได้รับอนุญาตเข้าถึงข้อมูลบัญชีลูกค้าผ่าน Online Customer Portal กระทบราว 400,000 บัญชีของ Georgia Power, Alabama Power และ Mississippi Power ข้อมูลที่เกี่ยวข้องรวมถึงชื่อ ที่อยู่ เบอร์โทร อีเมล และเลข Social Security 4 หลักท้ายในบางบัญชี โดยบริษัทระบุว่า Bank Account, Payment Card และ Driver’s License ไม่ได้อยู่ในข้อมูลที่ถูกเข้าถึง

ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

01 สถานการณ์

SecurityWeek รายงานคำยืนยันของ Southern Company ว่ามีบุคคลภายนอกที่ไม่ได้รับอนุญาตเข้าถึงข้อมูลจำกัดของบัญชีลูกค้าผ่าน Online Customer Portal ประมาณ 400,000 บัญชี โดยประมาณ 300,000 บัญชีเป็นลูกค้า Georgia Power และประมาณ 100,000 บัญชีเป็นลูกค้า Alabama Power ส่วน Mississippi Power ได้รับผลกระทบเช่นกันแต่ไม่เปิดเผยจำนวนแยก บริษัทไม่ได้เปิดเผยในข้อมูลที่ตรวจสอบได้ถึงวิธีที่ผู้โจมตีใช้เข้าถึง Portal

02 ผลกระทบ

ข้อมูลติดต่อและเลข Social Security 4 หลักท้ายสามารถเพิ่มความน่าเชื่อถือให้กับ Phishing, Vishing หรือ Social Engineering ที่แอบอ้างเป็นผู้ให้บริการสาธารณูปโภค อย่างไรก็ตาม ไม่มีข้อมูลยืนยันว่าเหตุการณ์นี้กระทบระบบผลิตหรือจ่ายไฟ จึงควรแยกผลกระทบด้านข้อมูลลูกค้าออกจากผลกระทบด้านการดำเนินงานของโครงสร้างพื้นฐานไฟฟ้า

03 ข้อเสนอแนะ

สำหรับองค์กรสาธารณูปโภคควรตรวจสอบ Authentication Log และพฤติกรรมผิดปกติของ Customer Portal บังคับใช้ Rate Limiting, MFA สำหรับบัญชีที่รองรับ และตรวจสอบ Session/Token ที่น่าสงสัย พร้อมแจ้งลูกค้าให้ระวัง Phishing ที่อ้างข้อมูลส่วนบุคคลจริง หากองค์กรอื่นใช้ Portal ลักษณะเดียวกันให้ทบทวนการป้องกัน Credential Stuffing และการตรวจจับ Automated Login
