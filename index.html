1. พบแคมเปญเจาะระบบ Check Point Security Management Servers หลายประเทศ

GreyNoise ยืนยันแคมเปญโจมตี Check Point Security Management Servers อย่างน้อย 24 เครื่องใน 17 ประเทศ กระทบอย่างน้อย 22 องค์กร รวมถึงหน่วยงานในประเทศไทยและภาคส่วนโครงสร้างพื้นฐานสำคัญ

สถานะ: Active intrusion campaign; victim notification ongoingเผยแพร่: 23–24 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

GreyNoise สังเกตกิจกรรมระหว่าง 17 ตุลาคม–2 พฤศจิกายน พบการใช้เครื่องมืออย่าง Nmap, Chisel, Impacket และ Paramiko เพื่อสำรวจระบบ ยกระดับสิทธิ์ เคลื่อนย้ายภายใน และนำข้อมูลออก นักวิจัยไม่ยืนยันผู้ก่อเหตุหรือช่องทางเจาะระบบเริ่มต้น จึงไม่ควรสรุป Attribution เพิ่มเติม

ผลกระทบ

ระบบบริหารจัดการความปลอดภัยที่ถูกยึดอาจเปิดทางให้เข้าถึงการตั้งค่าเครือข่าย บัญชีผู้ดูแล และระบบอื่นในองค์กร โดยกลุ่มเป้าหมายที่ยืนยันแล้วมีภาครัฐ พลังงาน การขนส่ง และการเงิน

ข้อเสนอแนะ

จำกัด Check Point Management interface ให้เข้าถึงเฉพาะเครือข่ายบริหาร อัปเดตผลิตภัณฑ์และระบบปฏิบัติการ ตรวจบัญชีผู้ดูแล Process และการเชื่อมต่อขาออกที่ผิดปกติ หากพบหลักฐานการยึดครองให้เปลี่ยนข้อมูลรับรองและพิจารณาสร้างระบบใหม่จากแหล่งที่เชื่อถือได้

2. Broadcom แก้ช่องโหว่ข้ามการยืนยันตัวตนใน VMware vCenter

VMware vCenterCVE-2026-123903Authentication Bypass

Broadcom เผยแพร่แพตช์ CVE-2026-123903 ระดับ Critical (CVSS 9.8) ซึ่งเปิดให้ผู้โจมตีจากเครือข่ายข้ามการยืนยันตัวตนของบริการ vmdir บน VMware vCenter ได้

สถานะ: Patch available; no workaroundเผยแพร่: 24 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

ประกาศของ Broadcom ระบุว่า VMware vCenter หลายสายผลิตภัณฑ์ได้รับผลกระทบ และไม่มีวิธีแก้ชั่วคราว สำหรับ vCenter 8.0 รุ่นแก้ไขคือ 8.0 U3m ส่วน vCenter 7.0 ที่มีสัญญา Extended Support ต้องติดต่อ Broadcom Support ทั้งนี้ประกาศไม่ได้ระบุว่าพบการใช้โจมตีจริง

ผลกระทบ

การข้ามการยืนยันตัวตนใน vCenter อาจเปิดทางให้ผู้โจมตีเข้าถึงระบบบริหารสภาพแวดล้อม Virtualization ซึ่งมีบทบาทสำคัญต่อ Workload และบริการจำนวนมาก

ข้อเสนอแนะ

อัปเดตตามตารางรุ่นที่ Broadcom กำหนดโดยเร่งด่วน รวมถึง VCF 5.x เป็น 5.2.5 จำกัด vCenter ให้อยู่ใน Management network และตรวจ SSO กับ Audit log หาความพยายามเข้าถึงที่ผิดปกติ โดยไม่รอวิธีแก้ชั่วคราวเพราะผู้ผลิตระบุว่าไม่มี

Broadcom Security Advisory

3. รายงานเหตุ Radware Cloud WAF เปิดเผยข้อมูลติดต่อและ Credential ส่งออก Log

Radware Cloud WAFCloud CredentialsUnauthenticated API

ตามรายงาน Root Cause Analysis ที่ BleepingComputer ได้รับ ผู้ไม่หวังดีเข้าถึง API บริหาร Cloud WAF ภายในของ Radware ซึ่งเปิดสู่อินเทอร์เน็ตโดยไม่ต้องยืนยันตัวตน และอาจเข้าถึง Credential ส่งออก Log ของลูกค้าบางราย

สถานะ: API access blocked; key rotation required; investigation ongoingเผยแพร่: 24 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

เหตุเกิดเมื่อ 19 พฤศจิกายน ข้อมูลที่อาจถูกเข้าถึงรวมข้อมูลติดต่อของลูกค้า และสำหรับลูกค้าบางส่วนมี Credential ที่ตั้งไว้ส่ง Log ไป AWS S3, Azure Blob Storage หรือ SFTP รายละเอียดนี้มาจากรายงาน RCA ที่สื่อได้รับ ไม่ใช่ประกาศสาธารณะบนเว็บไซต์ผู้ผลิต

ผลกระทบ

Credential ดังกล่าวอาจเปิดทางเข้าถึงพื้นที่จัดเก็บ Log ตามสิทธิ์ที่กำหนด ขณะที่รายงานระบุว่าไม่พบหลักฐานว่า Traffic ของ WAF, Certificate หรือ Application traffic ถูกเปิดเผย

ข้อเสนอแนะ

ลูกค้าที่ได้รับแจ้งควรเปลี่ยน AWS, Azure หรือ SFTP credential ทันที ตรวจ Cloud storage access log ตั้งแต่ 19 พฤศจิกายน ลดสิทธิ์ IAM ให้เหลือเท่าที่จำเป็น และติดตามผลสอบสวนจาก Radware โดยตรง

BleepingComputer — Radware breach report
