CRITICAL

1. Microsoft เตือนช่องทางเข้าถึง Azure APIM Classic ถูกใช้แตะต้องข้อมูลรับรอง

Microsoft AzureAPI Management ClassicCredential Exposure

Microsoft แจ้งลูกค้าว่าช่องทางเข้าถึง Management plane ของ Azure API Management Classic อาจถูกบุคคลไม่ได้รับอนุญาตใช้เข้าถึง Secret และข้อมูลรับรองที่จัดเก็บไว้ ก่อนบริษัทปิดเส้นทางดังกล่าวเมื่อ 19 พฤศจิกายน

สถานะ: Mitigated by Microsoft; customer credential rotation requiredเผยแพร่: 23 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Microsoft ตรวจพบปัญหาเมื่อ 18 พฤศจิกายนและดำเนินมาตรการแก้ไขในวันถัดมา เหตุเกี่ยวข้องกับ APIM Classic ที่ไม่ได้กำหนดค่าตามแนวทาง Network security ที่แนะนำ โดยข้อมูลที่อาจถูกเข้าถึงรวมถึง Named Values, Client secret ของ Identity provider และ OpenID Connect, Subscription key และ Token สำหรับ Direct management API ทั้งนี้ Microsoft ระบุว่า APIM v2 ไม่ได้รับผลกระทบ

ผลกระทบ

ข้อมูลรับรองที่ถูกเข้าถึงอาจใช้เชื่อมต่อ Application, Backend service หรือระบบอื่นตามสิทธิ์ของ Credential นั้น การแก้ไขฝั่ง Microsoft ไม่ได้เพิกถอนข้อมูลรับรองของลูกค้าที่อาจถูกเข้าถึงก่อนปิดช่องทาง

ข้อเสนอแนะ

ตรวจสอบ Azure Service Health สำหรับ Tracking ID MZK9-GH0 หมุนเวียน Secret, Subscription key และ Token ที่อยู่ใน APIM Classic ทันที ตรวจ Sign-in, Activity และ Backend log ย้อนหลัง และย้าย Secret ไปอ้างอิงจาก Azure Key Vault ตามแนวทางของ Microsoft

CRITICAL

2. พบการใช้ CVE-2026-84869 โจมตีเครื่องช่างเทคนิค ScreenConnect

ConnectWise ScreenConnectCVE-2026-84869Active Exploitation

Huntress ยืนยันการใช้ CVE-2026-84869 กับ ScreenConnect เพื่อส่งและรันไฟล์อันตรายบนเครื่องของช่างเทคนิค MSP โดยไม่แสดงคำยืนยันเมื่อช่างเชื่อมต่อ Remote session

สถานะ: Active exploitation observed; fixed in client 26.6.5+เผยแพร่: 23 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

ช่องโหว่อยู่ที่ ScreenConnect Client ไม่ใช่ Server และเปิดให้ Guest ใน Active remote session กระตุ้นการโอนไฟล์และรันไฟล์บน Host client ได้ Huntress พบการโจมตีจริงต่อเครื่องช่างเทคนิคเมื่อ 12 พฤศจิกายนและกิจกรรมเพิ่มเติม ขณะที่ ConnectWise ระบุว่าเวอร์ชัน 26.6.5 แก้ไขปัญหาแล้ว

ผลกระทบ

เครื่องช่างเทคนิค MSP มักเข้าถึง RMM console, Credential และระบบลูกค้าหลายองค์กร หากถูกยึดครองอาจนำไปสู่การติดตั้ง Remote access ที่ไม่ได้รับอนุญาต การขโมยข้อมูลรับรอง และการขยายผลไปยังลูกค้า

ข้อเสนอแนะ

ตรวจสอบให้ ScreenConnect Host client และ Access agent ทุกเครื่องเป็นเวอร์ชัน 26.6.5 หรือใหม่กว่า ไม่พิจารณาเฉพาะเวอร์ชัน Server ปิด TransferFiles permission ชั่วคราวหากยังอัปเดตไม่ได้ และตรวจหา Host client ที่ Spawn Script หรือไฟล์จาก Temp directory

3. Idunno.AntiCsrf มีช่องโหว่ RCE และพบการใช้โจมตีจริง

ASP.NETCVE-2026-131914Insecure Deserialization

Mandiant เปิดเผย CVE-2026-131914 ในไลบรารี Idunno.AntiCsrf รุ่นเก่า ซึ่งอาจเปิดให้ผู้โจมตีจากภายนอกส่ง HTTP POST เพื่อรันคำสั่งในบริบทของ IIS Worker process และยืนยันว่าพบการใช้โจมตีจริง

สถานะ: Active exploitation observed; no vendor patchเผยแพร่: 23 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

ช่องโหว่เกิดจากการ Deserialization ข้อมูล CSRF ที่ผู้โจมตีควบคุมโดยไม่มีการตรวจ MAC หรือ Signature ใน Idunno.AntiCsrf 0.9.1 Beta โครงการยุติการดูแลแล้วและไม่มี Patch ทางการ Mandiant ระบุว่าหน้า .aspx ที่เข้าถึงแบบไม่ยืนยันตัวตนอาจเปิดเส้นทางโจมตีด้วยคำขอเดียว

ผลกระทบ

การโจมตีสำเร็จทำให้รันคำสั่งด้วยสิทธิ์ของ w3wp.exe และอาจยึด Web application server เข้าถึง Secret ใน Web.config หรือ Database credential และวางไฟล์ไม่ได้รับอนุญาตใน Webroot

ข้อเสนอแนะ

ค้นหา Idunno.AntiCsrf.dll, AntiCsrfModule และการตั้งค่าที่เกี่ยวข้องใน Web.config ยุติการใช้งานและเปลี่ยนเป็น Anti-CSRF mechanism ที่ยังได้รับการสนับสนุน ตรวจ IIS log สำหรับ POST ผิดปกติและหากพบหลักฐานให้หมุนเวียน Secret พร้อมตรวจ Webroot และ Server โดยละเอียด

4. เกาหลีใต้สอบสวนเหตุข้อมูล KEPCO ON และระบบจัดซื้อ SRM รั่วไหล

KEPCOCritical InfrastructurePersonal Data

คณะกรรมการคุ้มครองข้อมูลส่วนบุคคลเกาหลีใต้เริ่มสอบสวนหลัง KEPCO รายงานว่าข้อมูลจากบริการลูกค้า KEPCO ON และระบบจัดซื้ออิเล็กทรอนิกส์ SRM ถูกผู้โจมตีคัดลอกออกไป

สถานะ: Investigation and victim support ongoingเผยแพร่: 22–23 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

KEPCO แจ้งหน่วยงานกำกับเมื่อ 22 พฤศจิกายน หลังได้รับอีเมลจากผู้โจมตีและตรวจพบตัวอย่างข้อมูลบน Dark web หน่วยงานกำกับระบุข้อมูล KEPCO ON ประมาณ 650,000 รายการ และข้อมูลผู้ใช้ SRM ประมาณ 870,000 รายการ โดยเป็นประชากรข้อมูลสองชุดที่ประกาศแยกกัน

ผลกระทบ

ข้อมูลที่เปิดเผยอาจรวมชื่อ เลขประจำตัว หมายเลขโทรศัพท์ หมายเลขลูกค้า บัญชีหรือบัตร ตลอดจนสังกัด เลขพนักงาน และอีเมล เพิ่มความเสี่ยง Fraud, Phishing และการสวมรอยต่อบุคลากรหรือคู่ค้า ทั้งนี้ยังไม่มีหลักฐานจากประกาศว่าการจ่ายไฟฟ้าถูกกระทบ

ข้อเสนอแนะ

องค์กรที่มีความสัมพันธ์กับ KEPCO หรือ SRM ควรแจ้งเตือนผู้ใช้ให้ระวังคำขอยืนยันตัวตนและลิงก์ไม่ทราบที่มา ตรวจธุรกรรมและ Account activity เปิด MFA ที่ทนต่อ Phishing และติดตามประกาศผลสอบสวนจาก PIPC/KEPCO เพื่อกำหนดขอบเขตตอบสนอง

HIGH

5. GlobeTopper เปิดเผยเหตุขโมย API Credential และแลก Gift Card โดยมิชอบ

GlobeTopperAPI CredentialsService Disruption

iQSTEL เปิดเผยว่าเหตุเข้าถึง GlobeTopper โดยไม่ได้รับอนุญาตทำให้ผู้โจมตีได้ API credential และ Integration key ของลูกค้าธุรกิจบางราย พร้อมแลก Gift card มูลค่าประมาณ 70,000 ดอลลาร์โดยมิชอบ

สถานะ: Contained; credentials rotated; investigation ongoingเผยแพร่: 20–23 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

เหตุเริ่มตรวจพบเมื่อ 22 ตุลาคมและมีการปิด Platform กับ Server ที่ได้รับผลกระทบในวันที่ 23 ตุลาคม บริษัทสร้าง Platform และ AWS environment ใหม่ก่อนทยอยคืนบริการตั้งแต่ 1 พฤศจิกายน และเปิดเผยรายละเอียดผ่านเอกสาร Form 8-K ในเดือนพฤศจิกายน

ผลกระทบ

เหตุทำให้บริการหยุดชะงัก กระทบ Transaction volume และเปิดเผย Credential ที่ใช้เชื่อมต่อ API ของลูกค้าธุรกิจ บริษัทยังอยู่ระหว่างตรวจสอบว่ามีข้อมูลลูกค้า ข้อมูลส่วนบุคคล ข้อมูลการชำระเงิน หรือข้อมูลผู้ให้บริการอื่นถูกเข้าถึงหรือไม่

ข้อเสนอแนะ

ลูกค้า GlobeTopper ควรยืนยันว่า API credential และ Integration key ถูกเปลี่ยนแล้ว ตรวจ API log ตั้งแต่ก่อน 22 ตุลาคม จำกัด Source IP และ Scope ของ Key แยก Credential ตามระบบ และติดตามการแจ้งเตือนเพิ่มเติมจากบริษัทโดยไม่สรุปขอบเขตข้อมูลเกินกว่าผลสอบสวน
