CRITICAL

1. Cisco Secure Email Gateway ถูกโจมตีผ่านช่องโหว่เขียนไฟล์และรันคำสั่งระดับ root

CVE-2026-76519Active Exploitation14 ต.ค. 2569

Cisco ยืนยันการใช้ CVE-2026-76519 โจมตีจริง ช่องโหว่ในฟังก์ชัน Advanced Malware Protection อาจเปิดทางให้ผู้โจมตีที่ไม่ผ่านการยืนยันตัวตนส่งไฟล์แนบที่สร้างขึ้นเฉพาะและรันคำสั่งระดับ root บนอุปกรณ์ได้

สถานะ: เร่งด่วนการดำเนินการ: ตรวจสอบตาม Advisory
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Cisco เปิดเผยเมื่อ 14 ตุลาคม 2569 ว่า CVE-2026-76519 มีความรุนแรง CVSS 9.8 และพบการใช้โจมตีจริง กระทบ Cisco Secure Email Gateway ที่ใช้ AsyncOS รุ่นที่มีช่องโหว่ เมื่อเปิด File Reputation ใน Mail Policy และใช้ Content Scanner Tools ก่อน 25.3.0.5525 ผู้ผลิตระบุว่าไม่มีวิธีแก้ชั่วคราวที่ทดแทนการอัปเดตได้

ผลกระทบ

ผู้โจมตีอาจเขียนไฟล์และรันคำสั่งด้วยสิทธิ์ root เข้าถึงข้อมูลบนอุปกรณ์ และอาจใช้กุญแจ SSH ของ Cluster ขยายผลไปยังสมาชิกอื่น หลักฐานบนอุปกรณ์อาจถูกลบหรือซ่อนได้หลังถูกยึดควบคุม

ข้อเสนอแนะ

ตรวจรุ่น AsyncOS และ Content Scanner Tools แล้วอัปเกรดเป็นรุ่นแก้ไขตาม Cisco Advisory ทันที ตรวจ system_logs ด้วยคำแนะนำของ Cisco รวมทั้ง Network/Firewall Logs ภายนอกอุปกรณ์ หากพบสัญญาณต้องสงสัยให้ติดต่อ Cisco TAC และเตรียมกู้คืนอุปกรณ์จากแหล่งที่เชื่อถือได้

แหล่งข้อมูล:Cisco

2. Palo Alto Networks พบการโจมตี PAN-OS Management Interface แบบจำกัดวง

CVE-2026-0322Limited Exploitation14 ต.ค. 2569

Palo Alto Networks ระบุว่า CVE-2026-0322 เป็นช่องโหว่ RCE ระดับ High และพบการโจมตีแบบจำกัดวง ผู้โจมตีต้องมีบัญชีสิทธิ์สูงและเข้าถึง Management Interface ผ่านเครือข่ายจึงจะรันโค้ดระดับ root ได้

สถานะ: เฝ้าระวังและดำเนินการการดำเนินการ: ตรวจสอบตาม Advisory

สถานการณ์

ประกาศวันที่ 14 ตุลาคมระบุว่าช่องโหว่กระทบ PAN-OS บน PA-Series, VM-Series และ Panorama ส่วน Cloud NGFW และ Prisma Access ไม่ได้รับผลกระทบ ผู้ผลิตจัดสถานะ Exploit Maturity เป็น ATTACKED และแนะนำให้แก้ไขเร่งด่วน โดยเฉพาะระบบที่เปิด Management Interface จากอินเทอร์เน็ต

ผลกระทบ

บัญชีผู้ดูแลที่ถูกยึดอาจถูกใช้รันโค้ดระดับ root เปลี่ยนการตั้งค่า Firewall เข้าถึงข้อมูลบนอุปกรณ์ หรือทำให้บริการหยุดชะงัก ความเสี่ยงสูงขึ้นเมื่อ Management Interface เปิดให้เข้าถึงจากภายนอก

ข้อเสนอแนะ

เทียบรุ่น PAN-OS กับตาราง Fixed Version ใน Advisory และอัปเดตโดยเร็ว จำกัด Management Interface ให้เข้าถึงได้เฉพาะ Trusted Internal IP หรือ Jump Box ตรวจบัญชีผู้ดูแล Session และ Log การจัดการย้อนหลังเพื่อค้นหากิจกรรมผิดปกติ

Microsoft และ Resecurity วิเคราะห์ระบบนิเวศภาษาจีนที่จำหน่ายโครงสร้างพื้นฐาน Cloud และ Phishing-as-a-Service ให้ผู้ก่อเหตุรายอื่น ชุดเครื่องมือเลียนแบบหน่วยงานรัฐ การเงิน โลจิสติกส์ และแบรนด์ต่าง ๆ เพื่อขโมยข้อมูลเข้าสู่ระบบและข้อมูลการเงิน พร้อมมีการดำเนินการร่วมกับพันธมิตรเพื่อรบกวนโครงสร้างพื้นฐานดังกล่าว

ผลกระทบ

ขนาดของโครงสร้างพื้นฐานทำให้ผู้โจมตีที่มีทักษะจำกัดสามารถสร้างแคมเปญจำนวนมากได้ บัญชี Cloud ที่ถูกขโมยหรือจัดหามาโดยมิชอบช่วยให้ข้อความดูน่าเชื่อถือและอาจนำไปสู่ Account Takeover การทุจริต และการเข้าถึงเครือข่ายองค์กร

ข้อเสนอแนะ

บังคับใช้ MFA ที่ต้าน Phishing ตรวจการสร้าง Application Credential และ Tenant ผิดปกติ ปรับ Mail/SMS filtering สำหรับโดเมนใหม่หรือแบรนด์เลียนแบบ และให้ผู้ใช้ยืนยันคำขอด้านการเงินหรือบัญชีผ่านช่องทางแยกเมื่อข้อความมีความเร่งด่วน

5. curl แก้ช่องโหว่ Use-After-Free ระหว่างอัปโหลดผ่าน HTTP/2

CVE-2026-92392Supply Chain14 ต.ค. 2569

โครงการ curl จัดระดับ CVE-2026-92392 เป็น High ช่องโหว่อาจทำให้เซิร์ฟเวอร์ปลายทางที่เป็นอันตรายกระตุ้น Memory Corruption บนเครื่อง Client ระหว่างอัปโหลดข้อมูลผ่าน HTTP/2 และมีการสาธิตการรันโค้ดภายใต้เงื่อนไขเฉพาะ

สถานะ: เฝ้าระวังและดำเนินการการดำเนินการ: ตรวจสอบตาม Advisory
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

ช่องโหว่กระทบ curl และ libcurl รุ่น 8.12.0 ถึง 8.22.0 รวมทั้งเครื่องมือบรรทัดคำสั่ง โครงการออก curl 8.23.0 เมื่อ 14 ตุลาคมพร้อม Advisory และระบุรุ่นย่อยบางสายที่ Backport การแก้ไขแล้ว ไม่พบข้อมูลยืนยันการใช้โจมตีจริงจากประกาศต้นทาง

ผลกระทบ

แอปพลิเคชันที่ใช้ libcurl อาจได้รับผลกระทบโดยผู้ดูแลไม่ทราบว่าเป็นส่วนประกอบภายใน การโจมตีต้องเกี่ยวข้องกับการอัปโหลด HTTP/2 ไปยังเซิร์ฟเวอร์ที่ผู้โจมตีควบคุม และอาจจบที่โปรแกรมล่มหรือรันโค้ดเมื่อเงื่อนไข Memory ตรงกัน

ข้อเสนอแนะ

จัดทำ Software Inventory เพื่อหา curl/libcurl ที่ฝังในระบบ อัปเดตเป็น 8.23.0 หรือแพตช์จากผู้จัดจำหน่าย หากยังแก้ไม่ได้ให้ปิดการใช้ HTTP/2 สำหรับงานอัปโหลดที่ไม่เชื่อถือ และตรวจ Crash หรือพฤติกรรมผิดปกติของบริการที่เกี่ยวข้อง
