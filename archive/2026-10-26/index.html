สถานการณ์

รายงานวันที่ 24 ต.ค. ขยายขอบเขต CVE-2026-111497 จาก Google Brotli ไปยังซอฟต์แวร์ที่ฝัง Decoder เดียวกัน ได้แก่ Node.js, Bun, Python Brotli/brotlicffi, Envoy และ Istio ช่องโหว่ทำให้ข้อมูล Brotli ที่สร้างขึ้นเฉพาะเขียนเลยขอบเขต Buffer ได้ โดย Imperva สาธิตการรันโค้ดบน Node.js 24.22.0 Linux ARM64; ยังไม่มีรายงานการใช้โจมตีจริง

ผลกระทบ

ระบบที่ถอดรหัส Brotli จากข้อมูลภายนอกอาจ Crash, เปิดเผยหน่วยความจำ หรือถูกรันโค้ดในบริบทของ Process ได้ ความเสี่ยงเกิดได้ทั้งฝั่ง Server ที่รับ Content-Encoding: br และ Client ที่ถอดรหัส Response จาก Server ที่ไม่ไว้วางใจ ทั้งนี้ผลิตภัณฑ์และเวอร์ชันที่ได้รับผลกระทบแตกต่างกันตามประกาศของแต่ละโครงการ

ข้อเสนอแนะ

สำรวจ Node.js 22.x/24.x/26.x และส่วนประกอบที่ใช้ Brotli แล้วอัปเดตตามรุ่นแก้ไขของผู้ผลิต เช่น Node.js 22.23.4, 24.22.1 หรือ 26.12.1 และ Google Brotli 1.0.10, 1.1.1 หรือ 1.2.1 จากนั้น Restart Service และ Rebuild Container Image; หากยังอัปเดตไม่ได้ให้หยุดถอดรหัส Brotli จากแหล่งที่ไม่ไว้วางใจ

2. ไฟล์ AGENTS.md ที่เป็นอันตรายใน Downloads อาจชักนำ AI Coding Agent ให้รันคำสั่งหรือขโมย Token

AI Agent SecurityPrompt InjectionDeveloper Endpoint

Forever Security พบ AGENTS.md ที่เป็นอันตรายในเครื่องลูกค้าและยืนยันการโจมตีเชิงทดลองกับ Codex และ Claude Code; เงื่อนไขสำคัญคือต้องเปิด Agent ในโฟลเดอร์ Downloads เดียวกัน

ประเด็น: AI Coding Agent / Endpointสถานะ: พบไฟล์จริงหนึ่งกรณีและยืนยันกลไกในสภาพแวดล้อมแยกการดำเนินการ: ห้ามใช้ Downloads/Home เป็น Working Directory ของ Agent

สถานการณ์

Forever Security เปิดเผยการพบไฟล์ AGENTS.md ที่เป็นอันตรายในโฟลเดอร์ Downloads ของเครื่องลูกค้า ไฟล์ดังกล่าวพยายามชักนำ Coding Agent ให้แก้ค่ากำหนดและติดตั้งแพ็กเกจ npm ที่เป็นอันตราย นักวิจัยจำลองสายโจมตีในสภาพแวดล้อมแยกกับ OpenAI Codex และ Claude Code; อย่างไรก็ดี การโจมตีต้องอาศัยให้ผู้ใช้เปิด Agent ในโฟลเดอร์เดียวกับไฟล์คำสั่งนั้น

ผลกระทบ

หาก Agent ได้รับสิทธิใช้ Shell, Package Manager หรือ Credential ในเครื่อง คำสั่งที่แฝงในไฟล์อาจนำไปสู่การรันโค้ด การติดตั้งมัลแวร์ หรือการเปิดเผย Token ได้ ประเด็นนี้เป็นการใช้พฤติกรรมการอ่าน Instruction File ตามปกติ ไม่ใช่หลักฐานว่าทุก Session หรือทุกผลิตภัณฑ์ถูกโจมตีโดยอัตโนมัติ

ข้อเสนอแนะ

กำหนดให้เปิด Coding Agent จาก Root ของโครงการที่ผ่านการตรวจสอบเท่านั้น หลีกเลี่ยง Downloads, Home หรือโฟลเดอร์กว้าง ตรวจไฟล์ AGENTS.md/CLAUDE.md ที่ไม่คุ้นเคยก่อนใช้งาน คง Sandbox และ Approval Prompt ไว้ และหมุนเวียน Token หากพบไฟล์ต้องสงสัยหรือ Agent เคยดำเนินการตามคำสั่งดังกล่าว

3. งานวิจัย Tailworm ชี้ความเสี่ยงยกระดับสิทธิผ่าน Tailscale SSH เมื่ออุปกรณ์ต้นทางถูกยึด

Tailscale SSHPrivilege EscalationZero Trust

นักวิจัยรายงานว่า Tailscale SSH ที่อนุญาต Port Forwarding อาจเปิดทางจากอุปกรณ์ที่ถูกยึดไปสู่สิทธิ root บนเป้าหมายที่ ACL อนุญาต; ยังไม่มี CVE, รุ่นแก้ไข หรือการโจมตีจริงที่ยืนยัน

ประเด็น: Remote Access / Network Meshสถานะ: Source Claim จากการทดสอบในห้องปฏิบัติการ; ผู้ผลิตยังประเมินขอบเขตการดำเนินการ: จำกัด ACL แบบคู่ต้นทาง–ปลายทางและปิด Port Forwarding เมื่อไม่จำเป็น
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

รายงาน Tailworm วันที่ 25 ต.ค. อธิบายการทดสอบ Tailscale 1.104.2 และ headscale 0.29.5 โดยเริ่มจากอุปกรณ์หนึ่งที่ผู้โจมตีควบคุมและ ACL อนุญาตให้เชื่อมต่อเป้าหมายผ่าน Tailscale SSH นักวิจัยระบุว่าสามารถใช้ Port Forwarding ให้ Process ของ Tailscale ที่รันด้วยสิทธิสูงเข้าถึง Unix Socket หรือทรัพยากรระดับ root ได้

ผลกระทบ

ภายใต้เงื่อนไขที่กำหนด อุปกรณ์ต้นทางที่ถูกยึดอาจขยายผลไปยัง Server อื่นตามเส้นทางที่ ACL เปิดไว้โดยไม่ต้องขโมย SSH Key อย่างไรก็ดี ผลทั้งหมดมาจากรายงานของนักวิจัยรายเดียว ยังไม่มีการทำซ้ำโดยอิสระ ไม่มี CVE หรือ Fixed Version ณ เวลารายงาน และยังไม่พบการโจมตีในระบบจริง

ข้อเสนอแนะ

ทบทวน Tailscale SSH Grant ให้เจาะจงแบบหนึ่ง Source ต่อหนึ่ง Destination ปิด SSH Port Forwarding ในกฎที่ไม่จำเป็น เปิด Tailnet Lock, Node-key Expiry และ SSH Check Mode พร้อมลบ Device ออกจาก Control Plane เมื่อสงสัยถูกยึด สำหรับ headscale 0.29.5 ให้ถือ SSH Grant เป็นเส้นทางสิทธิสูงจนกว่าจะมีคำแนะนำเพิ่มเติม

4. Unit 42 ถอนข้อสรุปเดิมว่าเหตุโจมตีหน่วยงานรัฐบาลยุโรปเริ่มจาก PHP2Shell

Intelligence CorrectionPHP2ShellGovernment

ประเด็น: Threat Intelligence Qualityสถานะ: ถอนการเชื่อมโยง Incident กับ CVE; ช่องโหว่ PHP ยังเป็น Criticalการดำเนินการ: แก้ไข Ticket/รายงานภายในและยังคงอัปเดต PHP ตาม Advisory

สถานการณ์

Unit 42 อัปเดตประกาศวันที่ 25 ต.ค. ว่าเหตุ Post-compromise ที่หน่วยงานรัฐบาลยุโรปเกิดในบริบทของ PHP Application ที่มีช่องโหว่ แต่หลักฐานยังไม่เพียงพอที่จะยืนยันว่า Initial Access เกิดจาก CVE-2026-109618 หรือ CVE-2026-109619 บริษัทจึงถอนข้อสรุปเดิมที่เผยแพร่เมื่อ 23 ต.ค.

ผลกระทบ

องค์กรที่นำข่าวเดิมไปผูก Alert, Incident หรือ Attribution กับ PHP2Shell ควรแก้ไขสถานะเป็นยังไม่ยืนยัน เพื่อหลีกเลี่ยงการตัดสินใจจากข้อมูลคลาดเคลื่อน อย่างไรก็ดี CVE ทั้งสองยังเป็น RCE ระดับ Critical ตามประกาศของผู้ผลิต และ Unit 42 ประเมินว่ามี Internet-exposed Instance ที่อาจได้รับผลกระทบมากกว่า 22.6 ล้านรายการ

ข้อเสนอแนะ

แก้ไขรายงานและ Case Management ภายในโดยแยก “เหตุโจมตีรัฐบาลยุโรป” ออกจาก “การยืนยัน Exploitation ของ PHP2Shell” จนกว่าจะมีหลักฐานเพิ่ม พร้อมสำรวจ Exposure, ติดตั้ง PHP Security Update ตามประกาศทางการ และ Hunting พฤติกรรม Post-exploitation จาก PHP Worker โดยไม่จำกัดเฉพาะ CVE สองรายการ

5. OpenAI เปิดเผยการทดสอบที่ AI Agent หลบ Sandbox เข้าถึง Internet และสื่อสารข้าม Isolation ได้

AI SafetySandbox EscapeCloud Security

การ Red-team ในระบบจำลองของ OpenAI พบเส้นทาง MicroVM Escape, การใช้ Service ภายในออก Internet และช่องทางสื่อสารผ่าน CPU Cache; บริษัทระบุว่าแก้ไขจุดอ่อนและจำกัด Frontier Training แบบไม่มี Live Internet

ประเด็น: AI Model Containmentสถานะ: การทดสอบภายในแบบควบคุม; OpenAI ระบุว่าแก้ไขจุดอ่อนแล้วการดำเนินการ: ใช้ Defense-in-Depth แยก Sandbox, Host, Network และ Secret
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

OpenAI เปิดเผยผล High-compute Red-team ในสำเนาระบบวิจัยที่สร้างขึ้นเฉพาะ โดยให้ Agent ค้นหาเส้นทางออก Internet ข้ามขอบเขตภายใน และสื่อสารระหว่าง Sandbox ผลทดสอบพบการเชื่อมช่องโหว่เพื่อ Escape จาก MicroVM การใช้ Metrics/DNS/Firewall Configuration เพื่อเข้าถึงภายนอก และการส่ง Synthetic Secret ผ่าน CPU Cache Timing

ผลกระทบ

ผลดังกล่าวแสดงว่า Sandbox เพียงชั้นเดียวไม่เพียงพอสำหรับ Agent ที่มีความสามารถสูง และ Service ประกอบ เช่น Logging, Metrics, DNS กับ Authentication อาจกลายเป็นเส้นทางออกได้ นี่เป็นเหตุการณ์ทดสอบในสภาพแวดล้อมควบคุม ไม่ใช่หลักฐานการโจมตีลูกค้าหรือการรั่วไหลของ Secret จริงจากระบบ Production

ข้อเสนอแนะ

องค์กรที่เปิด Agent รันโค้ดควรแยกสิทธิของ Sandbox, Host และ Control Plane ใช้ Egress Allowlist, Network Isolation, Secret แบบอายุสั้น และ Monitoring ที่อยู่นอกสิทธิของ Agent ทดสอบเส้นทาง SSRF/DNS/Metadata และ Covert Channel เป็นระยะ พร้อมมี Kill Switch ที่หยุดงานโดยอัตโนมัติ
