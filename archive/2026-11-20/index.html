CRITICAL

1. PHP ออก Security Release สำหรับทุกสาขาที่รองรับ

PHPWeb RuntimeSecurity Update

PHP เผยแพร่รุ่น 8.5.13, 8.4.28, 8.3.37 และ 8.2.36 เพื่อแก้ช่องโหว่ด้านความมั่นคงปลอดภัย โดยประกาศล่วงหน้าระบุว่าความรุนแรงสูงสุดอยู่ในระดับ Critical

สถานะ: Security Updates Availableเผยแพร่: 19 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

PHP Development Team ออก Security Release สำหรับ PHP ทุกสาขาที่รองรับ ได้แก่ 8.5.13, 8.4.28, 8.3.37 และ 8.2.36 หลังแจ้งล่วงหน้าว่ารอบนี้แก้ช่องโหว่ที่มีความรุนแรงสูงสุดระดับ Critical ทั้งนี้ ช่องโหว่ Critical ต้องอาศัยการตั้งค่าที่ไม่ใช่ค่าเริ่มต้นหรือสภาพแวดล้อมที่พบไม่บ่อย

ผลกระทบ

ระบบเว็บและบริการที่ใช้ PHP รุ่นก่อนหน้ามีความเสี่ยงตามช่องโหว่ที่แก้ไขในแต่ละสาขา โดยระดับผลกระทบจริงขึ้นกับรุ่น การตั้งค่า และรูปแบบการใช้งานของระบบ

ข้อเสนอแนะ

สำรวจ PHP ใน Production, Container และ Build Image แล้วอัปเดตเป็น 8.5.13, 8.4.28, 8.3.37 หรือ 8.2.36 ตามสาขาที่ใช้งาน ทดสอบความเข้ากันได้และตรวจ ChangeLog ของสาขานั้นก่อนนำขึ้นระบบ

PHP News Archive

2. Drupal Core Critical RCE ผ่านตัวติดตั้ง

DrupalCVE-2026-132165Remote Code Execution

Drupal แจ้งช่องโหว่ CVE-2026-132165 ซึ่งภายใต้เงื่อนไขเฉพาะอาจทำให้ผู้โจมตีใช้ install.php เพื่อติดตั้งระบบใหม่ ยึดเว็บไซต์ หรือรันโค้ดจากระยะไกล

สถานะ: Fixed Versions Availableเผยแพร่: 18 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Drupal Security Team จัดระดับ SA-CORE-2026-017 เป็น Critical 18/25 ช่องโหว่เกี่ยวข้องกับไฟล์ install.php และอาจนำไปสู่ Site Takeover หรือ Remote Code Execution ภายใต้เงื่อนไขเฉพาะ รุ่นที่ได้รับผลกระทบคือก่อน 10.6.22, ตั้งแต่ 11.0.0 ถึงก่อน 11.3.22 และตั้งแต่ 11.4.0 ถึงก่อน 11.4.13

ผลกระทบ

เว็บไซต์ Drupal ที่เข้าเงื่อนไขอาจสูญเสียความลับ ความถูกต้อง และความพร้อมใช้ของข้อมูลทั้งหมด หากผู้โจมตีสามารถใช้เส้นทางโจมตีที่เกี่ยวข้องกับตัวติดตั้งได้

ข้อเสนอแนะ

อัปเดต Drupal 10 เป็น 10.6.22, Drupal 11.3 เป็น 11.3.22 หรือ Drupal 11.4 เป็น 11.4.13 และปฏิบัติตามแนวทาง Securing the Drupal Installer โดยจำกัดสิทธิ์เขียนหรือเปลี่ยนสิทธิ์ของ settings.php

Drupal SA-CORE-2026-017

3. CISA เพิ่ม 4 ช่องโหว่ที่ถูกใช้โจมตีจริงใน KEV

CISA KEVActive ExploitationRCE

CISA เพิ่มช่องโหว่ของ Synology DSM, LiteLLM, Apache Axis และ REDCap รวม 4 รายการใน Known Exploited Vulnerabilities Catalog หลังพบหลักฐานการใช้โจมตีจริง

สถานะ: Active Exploitation Confirmed by CISAเผยแพร่: 18–19 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

รายการที่เพิ่มประกอบด้วย CVE-2024-10441 ใน Synology DSM, CVE-2026-40217 ใน BerriAI LiteLLM, CVE-2026-90436 ใน Apache Axis 1.x และ CVE-2026-90817 ใน Vanderbilt REDCap การอยู่ใน KEV ยืนยันว่ามีหลักฐานการใช้ช่องโหว่จริง แต่ไม่ได้ระบุว่าผู้โจมตีรายเดียวกันใช้ทั้งสี่ช่องโหว่

ผลกระทบ

องค์กรที่ใช้ผลิตภัณฑ์ดังกล่าวอาจเผชิญการรันโค้ดหรือเข้าควบคุมระบบตามคุณลักษณะของแต่ละช่องโหว่ โดยระบบจัดเก็บข้อมูล AI Gateway บริการเว็บรุ่นเก่า และระบบวิจัยสุขภาพอาจอยู่ภายใต้เจ้าของระบบต่างกัน

ข้อเสนอแนะ

ค้นหาทรัพย์สินทั้งสี่กลุ่ม แยกเจ้าของระบบ และดำเนินการตามคำแนะนำผู้ผลิตหรือยุติการใช้ผลิตภัณฑ์ที่ไม่มีการสนับสนุน ตรวจ Log และหลักฐานการบุกรุกย้อนหลัง เพราะการอัปเดตไม่สามารถยืนยันได้ว่าระบบไม่เคยถูกโจมตีมาก่อน

4. ASUS Control Center Express มีช่องโหว่ Hard-coded Cryptographic Key

ASUSControl Center ExpressCVE

ASUS แจ้งช่องโหว่หลายรายการใน Control Center Express Agent รุ่นก่อน 1.7.29 ซึ่งรวมความเสี่ยงจากกุญแจเข้ารหัสที่ฝังไว้ในผลิตภัณฑ์

สถานะ: Update Availableเผยแพร่: 18 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

ประกาศของ ASUS ระบุช่องโหว่ CVE-2026-114202, CVE-2026-114204 และ CVE-2026-114205 ใน Control Center Express Agent รุ่นก่อน 1.7.29 โดยมีประเด็นเกี่ยวกับ Hard-coded Cryptographic Key และกลไกควบคุมที่เกี่ยวข้อง

ผลกระทบ

ระบบบริหารจัดการอุปกรณ์ที่ยังใช้รุ่นก่อน 1.7.29 อาจมีความเสี่ยงต่อการเข้าถึงหรือจัดการโดยไม่ได้รับอนุญาต ขึ้นกับช่องโหว่และสภาพแวดล้อมการติดตั้ง

ข้อเสนอแนะ

ตรวจสอบเครื่องที่ติดตั้ง ASUS Control Center Express Agent และอัปเดตเป็น 1.7.29 หรือใหม่กว่า จำกัดการเข้าถึง Management Interface จากเครือข่ายที่เชื่อถือได้ และทบทวนบัญชีหรือเหตุการณ์ผิดปกติ

5. TfL แจ้งบัญชี Oyster Photocard ราว 265,000 รายอาจถูกเข้าถึง

Data BreachTransportPersonal Data

Transport for London ระบุว่าบัญชี Oyster Photocard ราว 265,000 รายอาจได้รับผลกระทบ หลังตรวจพบกิจกรรมน่าสงสัยและนำเว็บไซต์ Photocard ออกจากระบบชั่วคราว

สถานะ: Incident Contained; Investigation Ongoingเผยแพร่: 19 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

TfL ตรวจพบเหตุเมื่อ 16 พฤศจิกายน หลังลูกค้าได้รับอีเมลให้สร้างบัญชีใหม่ทั้งที่มีบัญชีอยู่แล้ว จึงปิดเว็บไซต์ Photocard เพื่อสอบสวน ข้อมูลที่อาจถูกเข้าถึงรวมชื่อและข้อมูลติดต่อ วันเกิด ตลอดจนคำถามและคำตอบรักษาความปลอดภัย โดย TfL ประเมินว่า Password ข้อมูลธนาคารหรือบัตรชำระเงิน ประวัติการเดินทาง และชื่อหรือวันเกิดของเด็กที่ถือ Zip Oyster Card ไม่ได้ถูกเข้าถึง

ผลกระทบ

ผู้ได้รับผลกระทบเสี่ยงต่อ Phishing, Social Engineering และการนำข้อมูลส่วนบุคคลไปใช้ประกอบการยืนยันตัวตน แม้ไม่มีหลักฐานว่าข้อมูลการชำระเงินหรือรหัสผ่านถูกเข้าถึง

ข้อเสนอแนะ

องค์กรควรแจ้งเตือนผู้ใช้ที่เกี่ยวข้องให้ระวังข้อความแอบอ้าง TfL เปลี่ยนคำถามและคำตอบรักษาความปลอดภัยที่ใช้ซ้ำกับบริการอื่น และติดตามการแจ้งเตือนจาก TfL ช่องทางทางการ

6. SBC Medical ยืนยันข้อมูลลูกค้า 1.624 ล้านรายถูกดึงออกจากระบบ

HealthcareData BreachJapan

SBC Medical Group เปิดเผยเหตุเข้าถึงฐานข้อมูลโดยไม่ได้รับอนุญาตในญี่ปุ่น และยืนยันว่าบุคคลภายนอกเข้าถึงพร้อมดึงข้อมูลลูกค้าพื้นฐานของ 1,624,000 ราย

สถานะ: Contained; Scope Under Investigationเผยแพร่: 18 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

SBC Medical Group ระบุว่าเมื่อ 16 พฤศจิกายน บุคคลภายนอกเข้าถึงฐานข้อมูลในระบบเว็บไซต์ของบริษัทย่อยในญี่ปุ่นและดึงข้อมูลออก ข้อมูลพื้นฐานที่อาจอยู่ในชุดข้อมูลประกอบด้วยชื่อ เพศ หมายเลขโทรศัพท์ อีเมล Password ที่อยู่ วันเกิด เลขบัตรผู้ป่วย Member ID และคำตอบแบบสำรวจทั้งหมดหรือบางส่วน นอกจากนี้ยังมีข้อมูลจากหมวดคำขอนัดหมาย แบบฟอร์มติดต่อ และเหตุแยกบนบริการ Tribeau; ขอบเขตเต็มยังอยู่ระหว่างสอบสวน

ผลกระทบ

ข้อมูลส่วนบุคคลและข้อมูลที่เกี่ยวข้องกับบริการสุขภาพสามารถเพิ่มความเสี่ยงจากการหลอกลวงเฉพาะบุคคล การยึดบัญชี และผลกระทบด้านความเป็นส่วนตัว บริษัทระบุว่ายังไม่ยืนยันการนำข้อมูลไปใช้โดยมิชอบ

ข้อเสนอแนะ

ผู้เกี่ยวข้องควรเปลี่ยน Password ที่ใช้ซ้ำ เฝ้าระวังอีเมลหรือการติดต่อแอบอ้างคลินิก และตรวจบัญชีที่เกี่ยวข้อง ฝ่ายองค์กรควรติดตามประกาศเพิ่มเติมและทบทวนความเสี่ยงของผู้ให้บริการภายนอก
