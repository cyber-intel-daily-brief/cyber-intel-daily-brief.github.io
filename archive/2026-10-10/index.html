01 สถานการณ์

Reuters รายงานเมื่อ 9 ต.ค. 2569 ว่า ธนาคารเกาหลีใต้ 9 แห่งและโบสถ์ขนาดใหญ่ 2 แห่งกำลังสอบสวนการโจมตีที่อาจเกี่ยวข้องกับเครื่องมือ AI ขณะเดียวกันบริษัทญี่ปุ่น รวมถึง Daiwa Securities, SoftBank และ Lawson เผชิญเหตุไซเบอร์หลายกรณี ทางการยังอยู่ระหว่างสอบสวนว่า AI ถูกใช้ในแต่ละเหตุการณ์หรือไม่

02 ผลกระทบ

ภาคการเงินและบริการสำคัญเผชิญความเสี่ยงจากการสแกนช่องโหว่ การหลอกลวง และการโจมตีที่ทำได้รวดเร็วขึ้น Reuters ระบุว่าเหตุในเกาหลีใต้ยังไม่ก่อความเสียหายทางการเงินอย่างมีนัยสำคัญ แต่ข้อมูลที่ถูกเข้าถึงอาจเพิ่มความเสี่ยงต่อ Phishing และ Smishing

03 ข้อเสนอแนะ

ให้องค์กรทบทวน MFA ที่ต้าน Phishing ตรวจพฤติกรรมเข้าสู่ระบบและการเรียกใช้ API ที่ผิดปกติ และทดสอบกระบวนการตอบสนองต่อเหตุแบบหลายระบบพร้อมกัน ภาคการเงินควรเร่งทำ Cybersecurity Self-assessment และติดตามคำแนะนำจากหน่วยงานกำกับ

01 สถานการณ์

StepSecurity เปิดเผยเมื่อ 9 ต.ค. 2569 ว่า ในวันที่ 8 ต.ค. ผู้โจมตีใช้บัญชีผู้ดูแลโครงการโอเพนซอร์ส 2 บัญชีเพิ่มไฟล์ security-audit.yml ปลอมเข้าสู่ 345 Repository ในช่วงเวลาสั้น ๆ โดยวิเคราะห์จาก Workflow ที่ถูกแทรก Metadata ของ Commit และ GitHub Actions Run Logs

02 ผลกระทบ

Workflow ถูกออกแบบให้ส่งออก GitHub Actions secrets และค้นหาข้อมูลรับรอง Cloud, AI และ SaaS จากทั้ง Working Tree และประวัติ Git หาก Workflow เคยทำงานแล้ว ความเสี่ยงไม่ได้จำกัดอยู่ที่ Repository ปัจจุบัน แต่รวมถึงความลับที่เคยบันทึกไว้ใน Commit เก่า

03 ข้อเสนอแนะ

ตรวจการเปลี่ยนแปลงใน .github/workflows และ Workflow runs วันที่ 8 ต.ค. จำกัดสิทธิ์ Workflow token บังคับ Review สำหรับไฟล์ Workflow และห้ามส่งออกไปยังปลายทางที่ไม่จำเป็น หากพบการทำงานของไฟล์ต้องสงสัย ให้เพิกถอนและหมุนเวียน Secrets ทุกชุดที่อาจถูกอ่านได้

01 สถานการณ์

Reuters รายงานเมื่อ 9 ต.ค. 2569 ว่า Holland & Knight และ Squire Patton Boggs เปิดเผยเหตุข้อมูลรั่วไหลต่ออัยการสูงสุดรัฐเวอร์มอนต์ Holland & Knight ระบุว่าผู้โจมตีใช้ Social Engineering เข้าถึงคอมพิวเตอร์ของสำนักงานจากระยะไกล ส่วน Squire Patton Boggs ระบุว่าบุคคลภายนอกเข้าถึงข้อมูลจำนวนจำกัด

02 ผลกระทบ

เอกสารที่เกี่ยวข้องมีหมายเลขประกันสังคมและข้อมูลลูกค้า ซึ่งอาจถูกนำไปใช้สวมรอยหรือสร้างการหลอกลวงเฉพาะบุคคล ทั้งสองสำนักงานระบุว่าเหตุไม่ทำให้บริการลูกค้าหยุดชะงัก และยังไม่มีข้อมูลที่ยืนยันขอบเขตผู้ได้รับผลกระทบทั้งหมด

03 ข้อเสนอแนะ

ให้องค์กรวิชาชีพทบทวนการให้สิทธิ์ Remote Access ใช้ MFA ที่ต้าน Phishing และกำหนดขั้นตอนยืนยันคำขอช่วยเหลือบัญชีด้วยช่องทางอิสระ ตรวจ Endpoint และบัญชีที่เข้าถึงเอกสารอ่อนไหว พร้อมแจ้งผู้ได้รับผลกระทบตามข้อกำหนดเมื่อยืนยันขอบเขตแล้ว

01 สถานการณ์

Reuters รายงานเมื่อ 8 ต.ค. 2569 ว่า Publica ซึ่งบริหารบำนาญให้พนักงานรัฐบาลกลางสวิสและองค์กรที่เกี่ยวข้อง ได้รับผลกระทบจากข้อมูลรั่วไหล หลังผู้ให้บริการซอฟต์แวร์ภายนอกถูกโจมตีเมื่อปลายเดือนกันยายน โดยยังไม่เปิดเผยชื่อผู้ให้บริการ

02 ผลกระทบ

ขอบเขตและประเภทข้อมูลที่ได้รับผลกระทบยังไม่ยืนยัน Publica และหน่วยงานที่เกี่ยวข้องกำลังตรวจสอบเหตุ อัยการสูงสุดสวิสเปิดการสอบสวน และ Publica ระบุว่าไม่มีหน่วยงานรัฐบาลกลางอื่นมีความสัมพันธ์ทางธุรกิจกับผู้ให้บริการรายดังกล่าว

03 ข้อเสนอแนะ

ให้องค์กรตรวจสอบผู้ให้บริการที่ประมวลผลข้อมูลบุคลากรหรือบำนาญ ขอหลักฐานการควบคุมสิทธิ์ การเก็บ Log และแผนแจ้งเหตุ กำหนดเส้นตายรับผลสอบสวนและเตรียมการแจ้งผู้ได้รับผลกระทบโดยไม่สรุปประเภทข้อมูลก่อนมีหลักฐานยืนยัน

กระทรวงการต่างประเทศอิตาลีแจ้งเมื่อ 8 ต.ค. 2569 ว่าเว็บไซต์ของกระทรวงเผชิญการโจมตีทางไซเบอร์ ระบบรักษาความปลอดภัยสามารถลดผลกระทบได้และไม่มีบริการหยุดชะงัก กระทรวงไม่ได้ระบุผู้ต้องสงสัยหรือวิธีการโจมตี

02 ผลกระทบ

ผลกระทบที่ยืนยันได้จำกัดอยู่ที่ความพยายามโจมตีเว็บไซต์ โดยยังไม่พบการหยุดให้บริการตามคำชี้แจง ขณะเดียวกันมีการตรวจสอบเพิ่มเติมว่าเว็บไซต์ของภารกิจทางการทูตและกงสุลในต่างประเทศเผชิญความพยายามคล้ายกันหรือไม่
