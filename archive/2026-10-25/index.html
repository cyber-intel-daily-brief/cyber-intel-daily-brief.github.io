CRITICAL

1. BlackX UEFI Bootkit หลบ Secure Boot ในปฏิบัติการจารกรรมที่มุ่งเป้าหน่วยงานการทูตเอเชียกลาง

Cyber EspionageUEFI BootkitCentral Asia

Kaspersky เปิดเผย BlackX UEFI Bootkit ซึ่งใช้ช่องโหว่ Baton Drop (CVE-2022-21894) เพื่อหลบ Secure Boot และติดตั้งไดรเวอร์ระดับ Kernel ในการโจมตีหน่วยงานการทูตในเอเชียกลางช่วงต้นปี 2569

ประเด็น: Government / Diplomaticสถานะ: Kaspersky ระบุ Attribution ต่อ APT41 ด้วยความเชื่อมั่นระดับปานกลางการดำเนินการ: ตรวจ Secure Boot, Boot Chain และพฤติกรรมระดับ Kernel
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Kaspersky GReAT เปิดเผย BlackX UEFI Bootkit ซึ่งพบในการโจมตีหน่วยงานการทูตในทาจิกิสถาน อุซเบกิสถาน และเติร์กเมนิสถานช่วงต้นปี 2569 โดยใช้ Baton Drop (CVE-2022-21894) เพื่อหลบ Secure Boot และโหลด EFI กับไดรเวอร์ Kernel ที่เป็นอันตราย รายงานระบุการเชื่อมโยงกับ APT41 ด้วยความเชื่อมั่นระดับปานกลาง จึงต้องถือเป็น Source Claim ไม่ใช่ข้อยืนยันเด็ดขาด

ผลกระทบ

การฝังตัวใต้ระบบปฏิบัติการทำให้ผู้โจมตีคงอยู่ข้ามการติดตั้งระบบบางรูปแบบ รบกวนกระบวนการรักษาความปลอดภัยและ Event Tracing for Windows และติดตั้ง Payload เพื่อการจารกรรมได้ เหตุการณ์มีนัยต่อหน่วยงานรัฐและการทูตในภูมิภาคเอเชีย แม้ยังไม่พบข้อมูลยืนยันว่ามีเป้าหมายในประเทศไทย

ข้อเสนอแนะ

ตรวจสอบว่าอุปกรณ์ Windows สำคัญเปิดใช้ Secure Boot และได้รับการอัปเดต Boot Manager ตามคำแนะนำของ Microsoft ใช้เครื่องมือที่เชื่อถือได้ตรวจ UEFI, Boot Chain, ไดรเวอร์ที่ลงนามผิดปกติ และความผิดปกติของ ETW หากสงสัยการติดเชื้อให้เก็บหลักฐานระดับ Firmware และใช้กระบวนการ Reimage ที่ครอบคลุม UEFI

Cloud SecurityData BreachPingCAP

PingCAP ยืนยันว่าผู้โจมตีใช้บัญชี GitHub และข้อมูลรับรองที่ถูกเปิดเผยเข้าถึงระบบภายใน ได้ Source Code และคัดลอกข้อมูลจากระบบ Analytics, Storage และ Support ระหว่าง 9 ก.ย.–7 ต.ค. 2569

ประเด็น: Cloud / Customer Dataสถานะ: ปิดเส้นทางเข้าถึงที่พบแล้ว แต่กำลังระบุผลกระทบรายลูกค้าการดำเนินการ: หมุนเวียน API Key และ Secret ที่เคยส่งให้ Support

สถานการณ์

PingCAP ระบุว่าระหว่าง 9 ก.ย.–7 ต.ค. ผู้โจมตีใช้บัญชี GitHub ที่ถูกยึดและข้อมูลรับรองที่ถูกเปิดเผยเพื่อเข้าถึงระบบภายใน ได้ Source Code และคัดลอกข้อมูลจากระบบ Analytics, Storage และ Support การสอบสวนภายนอกไม่พบหลักฐานว่าข้อมูลในฐานข้อมูล TiDB ของลูกค้าถูกเข้าถึงหรือมี Persistence ใน Production แต่ยืนยันว่าข้อมูลที่เกี่ยวข้องกับลูกค้าบางส่วนถูกคัดลอก

ผลกระทบ

ข้อมูลที่ถูกส่งออกอาจรวมชื่อ อีเมล ความสัมพันธ์กับองค์กรหรือโครงการ ข้อความและข้อผิดพลาดจาก SQL Editor ข้อมูลธุรกิจและ Billing ตลอดจนข้อมูลที่ลูกค้าเคยส่งใน Support Materials ค่า TiDB Cloud API Key ในตารางที่ส่งออกถูกเข้ารหัสและไม่พบกุญแจถอดรหัส แต่ข้อมูลรับรองที่เคยส่งให้ฝ่ายสนับสนุนอาจมีความเสี่ยง

ข้อเสนอแนะ

เปลี่ยน TiDB Cloud Management API Key และหมุนเวียน Password, Token, Key, Connection String หรือ Log ที่มี Secret ซึ่งเคยส่งให้ PingCAP Support ตรวจ Audit Log ของ GitHub, Cloud และ TiDB ตามช่วงเหตุการณ์ พร้อมยืนยันคำขอเปลี่ยนข้อมูลการชำระเงินหรือข้อมูลรับรองผ่านช่องทางที่เชื่อถือได้

5. Time4Popcorn รุ่นเก่ามีกลไกอัปเดตที่เปิดทางรันโค้ดระดับ SYSTEM หรือ root

CVE-2026-30612Insecure UpdaterEndpoint

Eye Research เปิดเผยว่า Time4Popcorn ติดต่อโดเมนอัปเดตที่ถูกทิ้งผ่าน HTTP และไม่ตรวจลายเซ็น ทำให้ผู้ควบคุมเส้นทางหรือโดเมนสามารถส่งโค้ดรันเป็น SYSTEM บน Windows หรือ root บน macOS

ประเด็น: Endpoint / Shadow ITสถานะ: นักวิจัยลดคำขออัปเดตได้ 98% แต่ความเสี่ยงบางส่วนยังคงอยู่การดำเนินการ: ถอน Time4Popcorn และค้นหา Updater ที่ตกค้าง
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Eye Research เปิดเผย Operation IXIM เกี่ยวกับ Time4Popcorn ซึ่งเป็น Fork ที่ถูกทิ้งและไม่เกี่ยวกับโครงการ Popcorn Time รุ่นใหม่ กลไกอัปเดตของ Windows และ macOS ติดต่อโดเมนที่หมดอายุผ่าน HTTP และไม่ตรวจ Digital Signature ทำให้ผู้ควบคุมโดเมนหรือดักแก้ Traffic สามารถส่งโค้ดรันด้วยสิทธิ SYSTEM หรือ root ได้ ช่องโหว่ได้รับ CVE-2026-30612

ผลกระทบ

นักวิจัยประเมินพบประมาณ 2.5–3.0 ล้านเครื่อง Windows และ 250,000–350,000 เครื่อง macOS พร้อมพบการเชื่อมต่อจากเครือข่ายองค์กร รัฐ และทหารทั่วโลก ตัวเลขดังกล่าวเป็นการประเมินของผู้วิจัย ไม่ใช่จำนวนเหยื่อยืนยัน นักวิจัยส่งคำสั่งปิด Updater ไปกว่า 2 ล้านครั้งและลดคำขอได้ 98% แต่ Android และตัวแอปเก่าที่ยังใช้ Engine ปี 2014 ยังมีความเสี่ยง

ข้อเสนอแนะ

ค้นหาและถอน Time4Popcorn/Popcorn Time รุ่นเก่าจาก Endpoint ทั้งขององค์กรและเครื่องที่ใช้เข้าถึงงาน ตรวจ Updater.exe และ PT.updd ที่ตกค้าง บล็อกการรันซอฟต์แวร์ไม่ได้รับอนุญาตด้วย Application Control และทบทวน EDR/Proxy Log เพื่อระบุเครื่องที่ยังติดต่อ Infrastructure ของ Updater
