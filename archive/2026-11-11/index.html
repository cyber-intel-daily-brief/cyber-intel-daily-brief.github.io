Microsoft OutlookCVE-2026-124194Active Exploitation

สถานะ: ถูกใช้โจมตีจริง; มี Security Update แล้วเผยแพร่: Microsoft / CISA / รายงาน 10 พ.ย. 2569

สถานการณ์

Microsoft แก้ CVE-2026-124194 ใน Outlook และระบุว่าพบการนำไปใช้โจมตีจริง ผู้โจมตีที่ไม่ผ่านการยืนยันตัวตนสามารถส่งไฟล์ข้อความที่สร้างขึ้นเฉพาะและโน้มน้าวให้ผู้ใช้เปิด เมื่อเปิดแล้ว Outlook อาจเชื่อมต่อไปยังตำแหน่งเครือข่ายของผู้โจมตีโดยไม่แสดงคำเตือน External Content ตามปกติ

ผลกระทบ

การเชื่อมต่อดังกล่าวอาจเปิดเผยข้อมูลยืนยันตัวตนแบบ NTLM ซึ่งผู้โจมตีอาจนำไปใช้ปลอมตัวเป็นผู้ใช้หรือสนับสนุนการเข้าถึงระบบภายใน เหตุการณ์ต้องอาศัยการเชื่อมต่อเครือข่ายและการกระทำของผู้ใช้ แต่มีหลักฐาน Active Exploitation แล้ว

ข้อเสนอแนะ

ติดตั้ง Security Update เดือนพฤศจิกายนของ Microsoft Office/Outlook โดยเร็ว จำกัดหรือปิด NTLM ไปยังเครือข่ายภายนอกตามความเหมาะสม และตรวจ Log ของ Firewall/Proxy/Windows สำหรับการเชื่อมต่อ SMB หรือ WebDAV ผิดปกติจากเครื่องผู้ใช้ หากพบเหตุให้รีเซ็ต Credential และตรวจสอบการใช้งานบัญชีต่อเนื่อง

Xen OrchestraVSA-2026-062Virtualization

Vates ยืนยันการโจมตี VSA-2026-062 ซึ่งใช้ Cookie ที่สร้างขึ้นเฉพาะเพื่อข้ามการยืนยันตัวตน รับสิทธิ Admin และอาจต่อยอดยึด XCP-ng Node ระดับ Root

สถานะ: Active Exploitation; รุ่นแก้ไขเผยแพร่แล้วเผยแพร่: Vates 10 พ.ย. 2569
ดูรายละเอียดสถานการณ์ ผลกระทบ และข้อเสนอแนะ

สถานการณ์

Vates เปิดเผย VSA-2026-062 ระดับ Critical ใน Xen Orchestra และ Xen Orchestra Appliance โดย REST Cookie Parsing อาจยอมรับ Empty Object แทน Token ที่ถูกต้อง ทำให้ผู้โจมตีที่เข้าถึง Management Interface ข้ามการยืนยันตัวตนและได้สิทธิ Admin ผู้ผลิตยืนยันว่าพบการใช้ช่องโหว่นี้โจมตีจริง

ผลกระทบ

เมื่อได้สิทธิผู้ดูแล Xen Orchestra ผู้โจมตีอาจดำเนินคำสั่งบน Managed Pool และต่อยอดยึด XCP-ng Node ด้วยสิทธิ Root ส่งผลต่อ Virtual Machine, Storage และระบบงานจำนวนมากที่อยู่ภายใต้ Management Plane เดียวกัน

ข้อเสนอแนะ

อัปเดต Xen Orchestra เป็น 6.9.1 (stable) หรือ 6.10.0 (latest) และตรวจสอบ xo-server ตามเวอร์ชันที่ Vates ระบุ ห้ามเปิด Management Interface สู่อินเทอร์เน็ตโดยตรง แยกไว้ใน Dedicated Management Network และดำเนิน Compromise Check ตามรายการไฟล์/VM/Log ใน Advisory ก่อนถือว่าการอัปเดตเสร็จสิ้น

สถานการณ์

ESET Research เปิดเผยชุดเครื่องมือ Cereal ซึ่งออกแบบสำหรับ Microsoft Exchange Server เพื่อรับคำสั่ง ทำงานใน Memory สำรวจเครือข่าย และเลือกเก็บอีเมล นักวิจัยพบในหน่วยงานรัฐคาซัคสถานและโรมาเนียช่วงปลายปี 2568 โดยระบบในโรมาเนียถูกตั้งค่าให้ค้นหาอีเมลที่เกี่ยวข้องกับ NATO และ EU และ ESET ระบุ Attribution ต่อ Turla ด้วย High Confidence

ผลกระทบ

การฝัง Module ในกระบวนการ Exchange ที่ถูกต้องช่วยให้ผู้โจมตีเฝ้าติดตามอีเมลระยะยาวโดยไม่ต้องมี C2 ภายนอกที่ชัดเจน ส่งผลต่อความลับของการสื่อสารภาครัฐ การทูต และความมั่นคง รวมถึงอาจเปิดทางเข้าถึงเครือข่ายภายใน

ข้อเสนอแนะ

ตรวจ Exchange Server สำหรับพฤติกรรม Process Injection, .NET Assembly และ Web Path ผิดปกติตามรายงาน ESET เก็บ Memory/Forensic Evidence ก่อนกำจัดระบบที่ต้องสงสัย จำกัดการเข้าถึง Exchange Management และตรวจสอบ Transport Process/Agent พร้อมใช้ Detection และ IOC ที่ ESET เผยแพร่โดยตรง

สถานการณ์

Fireworks AI อัปเดตเหตุเดือนตุลาคมว่า Third-party Cloud Provider ที่โฮสต์ R&D Machine ประสบเหตุเมื่อ 23 ตุลาคม และวันถัดมาผู้ไม่หวังดีใช้ช่องทางดังกล่าวเข้าถึง Development Machine พร้อมรัน Unauthorized Workload บริษัทระบุว่ามีผลกระทบต่อ Resource Metadata, Billing Information และ Dataset/Model Weight ที่ไม่สมบูรณ์ของลูกค้าบางส่วน

ผลกระทบ

เหตุการณ์ขยายความเสี่ยงจาก Development Environment และผู้ให้บริการ Cloud ภายนอกไปยังข้อมูลลูกค้าและทรัพย์สิน AI แม้ Fireworks ระบุว่าไม่เก็บหมายเลขบัตรชำระเงิน แต่ข้อมูล Billing และ Artifact ของ Model/Dataset อาจมีความละเอียดอ่อนต่อธุรกิจ

ข้อเสนอแนะ

ลูกค้าที่ได้รับการแจ้งควรทบทวน Resource และ Key ที่เกี่ยวข้องกับ Fireworks หมุนเวียน Credential ตามคำแนะนำของบริษัท ตรวจ Usage/Charge และ Download ผิดปกติ พร้อมประเมินว่าข้อมูลหรือ Model Artifact ใดอยู่ในขอบเขต องค์กรควรกำหนด Least Privilege และแยก Secret ระหว่าง Production กับ R&D Provider
